# Project instructions

## Product and scope

GitHub Profile Generator is a visual README generator for GitHub profiles. It offers five optional fixed sections: introduction, technologies, projects, activity and contributions, and contact, plus repeatable custom sections with optional titles. It should serve people with different levels of knowledge and public activity. GitHub activity does not determine a person's skill.

The current release includes the Next.js foundation, a bilingual visual kit, `ProfileDocument` version 2, and a concise profile editor with preview, copy, download, and a local draft. `sectionOrder` combines references to fixed and custom sections; `customSections` contains paragraphs, lists, links, subheadings, dividers, highlighted text, public images, explicitly filtered HTML, and literal code, with independent duplication, inclusion, and deletion. Presentation and custom titles, subtitles, and paragraphs have bounded level and alignment controls. Activity and contributions brings together manual contributions and ten optional card types: five built in and five adapted from GitHub Stats Extended, using public data and validated appearance. GitHub queries require server-only configuration and an explicit action; WakaTime uses a separate public username. The manual workflow requires no account or credentials. Exportable cards require a public HTTPS origin to host them. Skills, education, and current activity remain retired; their legacy structures and internal references are preserved. The editor includes local README import by pasting text or opening a `.md` file, review of custom sections, and confirmation with a backup of the previous profile and original Markdown. There is no AI assistance. Authored HTML is interpreted only in its explicit block; visual formatting derives escaped HTML under the same policy. Do not present an unconfigured integration as an enabled service.

Do not use projects announced as unmaintained, deprecated, or archived; evaluate active successors by their own repositories. ## Architecture and code

- Use the Next.js App Router and strict TypeScript. Keep routes and layouts small; put behavior in the scope that owns it.
- Keep English as the default language and Spanish as a fully supported option. Use `next-intl`, routes under `src/app/[locale]`, and message namespaces; avoid hard-coded interface text in components. Changing languages preserves the equivalent route, uses language names without flags, and keeps the correct `lang` attribute.
- Prefer Server Components. Use `"use client"` at the smallest boundary that needs state, events, or browser APIs. Do not convert an entire layout into a client component for convenience.
- Render available content first and isolate independent waits. Add loading states and `Suspense` where they address a real wait.
- Keep the model, its rules, and README generation in `src/core/`, without React, Next.js, network access, storage, or secrets. Validate unknown inputs with `parseProfileDocument`; operations and `generateReadme` receive documents that are already valid. Structural validation of a draft does not prove it is exportable: honor generator errors, plain text, and the link policy.
- Derive the preview, copy, and download from the same generated Markdown. The explicit `html` block is the only authored input interpreted as HTML; visual formatting builds elements with escaped text and uses the same policy and `customHtml`. Preserve `skipHtml` for everything else and do not create another README output. Keep the local draft outside `core`; recover and validate it before enabling writes, and retain invalid or inaccessible values until the user makes an explicit decision.
- README import uses `src/core/import/`: parse the complete AST with limits, resolve global references, and retain source and ranges before splitting. Propose only custom sections with existing blocks; do not infer fixed modules or introduce raw Markdown. Convert complex structures using the current HTML policy, reporting changes and errors. The review shows inert code without loading images or cards. Pasting, analyzing, excluding, or canceling does not modify the profile. See [ADR 0018](docs/decisions/0018-readme-import-with-backup.md).
- Confirming an import first saves the complete previous profile and the exact original Markdown under `github-profile-generator.import-backup.v1`, outside `ProfileDocument`. Preserve invalid records, the v1 key, and protected values. If saving fails, require an explicit action to continue in memory only, without re-enabling autosave. Invalidate earlier debounces and flushes; download both backups separately and restore with confirmation while retaining the record. Keep only one latest backup; this is not a history or general JSON import.
- The current format is v2 with `sectionOrder` and `customSections`; do not persist `moduleOrder` in new documents. Every fixed and custom reference must appear exactly once. Read `github-profile-generator.profile.v2` first; only if it is missing, validate and migrate v1 in memory. Do not write during recovery, overwrite or delete the v1 key, or use it as a fallback for an invalid v2. The first edit saves v2. See [ADR 0013](docs/decisions/0013-custom-sections.md).
- Custom sections are independent instances with optional titles and `paragraph`, `list`, `link`, `heading`, `divider`, `quote`, `image`, `html`, and `code` blocks. The selector offers ten options with decorative local samples; adding one does not insert example text. Duplicating copies every block and formatting option and assigns new IDs to items; hiding preserves the tree, while deleting removes only that instance and its reference. Keep keyboard assistance and list conversion limited to paragraphs and lists in the custom-section form; do not apply them to HTML or literal code. The v2 extension is additive: do not change keys or legacy structures or add default fields to existing blocks. A strict older reader may reject new types or properties and must preserve the value. See [ADR 0014](docs/decisions/0014-custom-visual-blocks.md), [ADR 0015](docs/decisions/0015-explicit-profile-html.md), and [ADR 0019](docs/decisions/0019-code-and-formatting.md).
- `code` stores exactly `{ id, type: "code", source, language }`. Preserve the source, BOM, spaces, and line breaks when editing, recovering, or duplicating; an empty language means plain text. Normalize aliases through `core/code` and accept safe unknown tokens up to 64 units. Generate fences longer than any run of backticks in the source. Keep export limits at 30,000 UTF-16 units per block and 150,000 units of visible code per document, with `invalid_code` on `source` or `language`; never truncate data. Import preserves fenced and indented code and its language when they are independent; discarded metadata produces a warning, and ambiguous HTML retains its structure. Code and icons written inside a fence remain text with no active resources.
- Custom formatting: `paragraph.alignment?`, `heading.level?/alignment?`, and `customSection.titleLevel?/titleAlignment?` accept left/center/right and levels 1/2/3 where applicable. Absence preserves the previous output; do not persist defaults during recovery. Center and right alignment derive escaped and validated HTML, sharing `customHtml` limits, trees, and ranges; their `invalid_html` errors point to `text` or `title`. Do not enable HTML in ordinary text or automatically center lists or code.
- Presentation supports `data.presentation.format?` only in v2: optional name/headline levels and name/headline/bio/location alignment, compatible typography, and `locationPlacement?: "displayName" | "headline"`. Do not add an automatic greeting option to the contract. The name and headline are centered by default; an explicit alignment can change them. The country/location field appears after About you and can be placed beside the name or headline with `from`/`desde`, or on its own line. Help text suggests writing the full headline without adding greetings to the document. Do not infer a profession or country or insert examples into the profile. Keep `moduleContentV1Schemas` closed; do not add defaults during recovery or alter text when resetting formatting. Derived HTML shares its budget and ranges with custom sections and retains the catalog flag; an overflow in the combined field points to the location and destination. See [ADR 0020](docs/decisions/0020-presentation-formatting.md) and [ADR 0034](docs/decisions/0034-friendly-presentation.md).
- “Borrar README” requires confirmation in the UI and uses `clearReadme`; it empties all profile data while preserving the language, v1, and import backup. Invalidate pending saves and revalidate storage before writing. Protected values, read/write failures, or an import kept only in memory preserve the protection and show that the profile was cleared only in memory. Do not confuse this with authorizing replacement of an inaccessible draft or purging all backups.
- Project files let users download the complete current document and open a local v1/v2 JSON file for review and confirmation, whether or not the README is exportable. `core/project` enforces 4 MiB UTF-8, depth 32, and 50,000 values; it preserves source and options, exports v2 in readable or compact form near the limit, and guarantees that the file can be reopened. Do not load candidate resources during review. Keep `project-backup.v1` separate from the Markdown backup, with the previous v2 profile available for download; do not overwrite protected keys. `replaceWithProject` and `restoreProjectBackup` invalidate pending saves, and failures require an explicit choice to continue in memory without re-enabling autosave. Closing or changing the language discards the proposal, not the draft. See [ADR 0021](docs/decisions/0021-project-files-and-recovery.md).
- `CodeEditor` loads CodeMirror and the parsers for all suggested languages on demand inside a small client boundary, and offers plain text as an alternative. Preserve the exact source, selection, per-block history, and accessible states; syntax highlighting does not validate or expand the HTML policy. Tab must leave the editor; indentation has its own commands and buttons, and scrolling stays local. The code preview uses local text and spans, with no execution or remote services.
- Add user images through `image` or inside a validated `html` block, using a publicly accessible HTTPS URL. `image` requires a non-empty alternative description for export; HTML requires the `alt` attribute and accepts `alt=""` as an explicit decorative choice. URL validation is syntactic: reject IP addresses, local hosts, credentials, fragments, and non-standard ports, without resolving DNS or checking availability. Do not upload files or accept local, relative, `blob:`, or `data:` paths. `customImages` contains exact pairs of canonical URL and normalized alternative text from `image` blocks; HTML images are authorized within `customHtml`, without mixing them or persisting metadata. Load images directly in the browser with `loading="lazy"`, `decoding="async"`, and `referrerPolicy="no-referrer"`, without a proxy or server optimizer. A load failure is temporary and does not invalidate an accepted URL.
- The `html` block stores exactly `{ id, type: "html", source }`; preserve the authored source, including when it has errors, without replacing it with filtered HTML. `analyzeProfileHtml` is pure and uses an HAST AST with an explicit schema: it accepts profile HTML, alignment, and bounded dimensions, but no CSS, JavaScript, full pages, events, IDs, classes, `srcset`, `picture`, or inline SVG. Links use absolute HTTP/HTTPS only; relative links and `#anchors` need correction and are not resolved against the application. Keep filtering warnings, a limit of 30,000 UTF-16 units per block, 1,500 nodes, depth 32, and a budget of 150,000 units of visible HTML per document. `invalid_html` errors point to `source` and block export; hidden sections do not participate. `customHtml` is derived metadata containing HTML, an allowed HAST tree, exact UTF-16 ranges in the final Markdown, and `headingLevel: 3 | 4`; verify the match before traversing that tree using allowed React elements, without `dangerouslySetInnerHTML`, `rehypeRaw`, or global HTML parsing. Preserve h1–h6 in export and adapt semantic levels only in the preview. Do not interpret Markdown inside `source` or promise parity with GitHub. See [ADR 0015](docs/decisions/0015-explicit-profile-html.md).
- Keep the workflow focused on a brief personal introduction. The introduction lets people share interests and what they are currently doing without repeating them in extra forms. Offer secondary details when useful and preserve data from older drafts, without turning the editor into a CV or requiring a work history to finish.
- Do not reintroduce skills, education, or current activity as options, legacy forms, or README output. Preserve their internal v1 structures and positions while editing or reordering the five active sections. Structural validation still applies to the complete document, but the generator does not validate links or content in retired modules.
- Distinguish selection, visibility, and deletion: configuring a section does not hide it; hiding preserves its data; removing an entry explicitly deletes it. The checkbox changes inclusion only and preserves focus; adding and editing a hidden section are identified actions. Keep the active selection, mobile navigation, and dragging as ephemeral state outside the document. When reordering included sections, preserve hidden, retired, and metrics references in their positions. Use keys that distinguish fixed references from custom ones; confirm the order only after a valid move completes and preserve it when a move is canceled.
- Activity and contributions use the fixed `contributions` reference and effective inclusion `visibility.contributions || visibility.metrics`; do not offer metrics as a separate fixed section. Hiding it from navigation turns off both flags; showing it again enables contributions and enables metrics only if selected cards remain. Recovering a draft does not rewrite flags. Keep every card type disabled initially, the panel collapsible, manual contributions available without a username, and suggestions as explicit choices.
- V2 contribution items add optional `links` (up to ten), `images` (up to three public HTTPS images with non-empty alt text), and retain legacy `repository` preview data only for compatibility. Use `url` when `links` is absent; do not rewrite v1 or migrate fields on recovery. Preserve contribution order and offer explicit Move up/Move down actions. Render old repository details as an ordinary link and description; do not offer a separate preview or fetch metadata. Derived image markup uses the shared filtered HTML budget and exact `customHtml` ranges, not `customImages`. See [ADR 0039](docs/decisions/0039-contribution-details-and-order.md).
- Save only `metrics.username/cards/appearance?/extended?/cardColumns?/contentOrder?` and the chosen contributions. V2 adds `extended-repository`, `extended-gist`, and `extended-wakatime` to its seven previous IDs; v1 keeps its original three IDs. `cardColumns` is optional, limited to 1 or 2, and defaults to 2 only when creating a new profile; absence after recovery or migration keeps the previous one-card-per-row output. Preserve selected card order and place an odd final card in its own row. In two-column mode, make the same local/public SVG renderers increase text size. `contentOrder` chooses whether activity or manual contributions appear first; absence preserves activity-first order. Preview the same GFM table Markdown with `remark-gfm`. Appearance combines presets, 79 themes, and validated colors/dimensions, with no CSS or URLs. `extended` limits statistics, filters, languages, twelve repositories/twelve Gists, and a separate WakaTime username. Do not insert defaults during recovery; reset removes appearance only. Snapshots are ephemeral, validated, and associated with identity/options; distinguish zero, partial, and absent data. «Buscar datos», below the username, works without cards and fetches common data. Afterwards, choosing components for the searched account reuses coverage and queries only missing data, with a 300 ms debounce; valid applied resources may also be loaded after Search. An identity that has not been searched requires another explicit action. Customizing data already covered renders local SVG with the same pure renderers, without HTTP SVG or JSON. Do not query on mount, recovery, opening, or entering the username. Progressive loading, errors, and retry respect reduced motion and do not loop on failures. Preview Blobs are internal and revocable and do not extend image or HTML support. Replacing or clearing the profile cancels and clears the cache and activation state. Public cache data may be persisted temporarily in separate IndexedDB storage under ADR 0031; never in `ProfileDocument`, Markdown, or backups. Optional contribution search is independent. See [ADR 0024](docs/decisions/0024-extended-public-suite-and-mit.md), [ADR 0027](docs/decisions/0027-browser-activity-data-cache.md), and [ADR 0029](docs/decisions/0029-account-first-activity-search.md).
- The five Extended families adapt pinned MIT code and render locally through the app's own public clients, with no hosted chart service. Preserve notices and licenses. Panorama distinguishes the period from the language sample; monthly activity sums UTC days and identifies partial months. Do not aggregate metrics with no data. The authorized ranking is optional and disabled initially: it uses Extended's formula with all six inputs present, does not assess skill or represent an observed population percentile, and is hidden when data is null or partial. Do not infer levels. Validate routes and options exactly; allow only bounded hexadecimal colors and gradients, with no CSS, animations, hosts, or free-form parameters. See the [compatibility matrix](docs/github-stats-extended.md).
- The server accepts a dedicated classic PAT and verifies that `x-oauth-scopes` is present, empty, or exactly `public_repo` before fetching data. Prefer only `public_repo` for GraphQL queries of public repositories; do not add `repo`, `read:user`, or other scopes. Reject credentials that cannot be verified, including fine-grained tokens. The client performs read-only queries even though the public scope permits other operations. Keep `GITHUB_TOKEN` out of Git and the browser. `APP_URL` is a configured public HTTPS origin, never derived from Host. If it is empty, only Vercel with `VERCEL_ENV=production` may resolve `VERCEL_PROJECT_PRODUCTION_URL` as a bare HTTPS domain under the same policy; an explicit, non-empty invalid value does not enable a fallback. Do not use `VERCEL_URL`, branch aliases, or request data. Without a valid origin, `generateReadme` allows reviewing the same Markdown with local paths and returns `exportIssues: activity_not_configured`; copy and download remain disabled until cards are deselected or a public host is configured. See [ADR 0010](docs/decisions/0010-github-activity.md) and [ADR 0036](docs/decisions/0036-production-card-origin.md).
- Offer technologies through the curated local catalog, autocomplete, icon chips, and a custom-text alternative. Suggest editable categories when adding an item, honor the selected destination, and do not regroup drafts during recovery or language changes. Organizing by category is an explicit action; removing a heading preserves its tools. Preserve legacy structures, opaque IDs, order, and contexts. Icons come from Devicon, Simple Icons, and Lobe Icons pinned to commits, with local SVGs and attribution. Export decorative icons at 20 × 20 beside the visible name and keep preview compatibility with the previous 32 × 32 markup. An AI tool in the catalog does not imply AI integration.
- In Contact, add the entry first, then choose a provider, personal website, or email and URL. Focus the selector when adding, preserve focus when choosing, and advance with Tab. Allow repeated entries and keep a single add button. Resolve the icon from the validated URL and explicit domains, never from the label or ephemeral selection; preserve v1 `links` without an added provider. Changing the selection does not replace the URL or name. Icons are decorative at 20 × 20, and a custom label is optional. Preserve shared normalization and errors.
- Location is optional and preserves free text. Offer EN/ES country names and flags from `core/location`, with an explicit choice through a combobox. Store the Unicode prefix and name in v1 `location`; generate only decorative 20 × 15 SVGs from the pinned flag-icons catalog. Do not use geolocation, infer countries from previous locations, or translate saved text when the interface language changes. Preserve exact image tokens, local copies, and the MIT license.
- Do not interpret HTML or image syntax written in ordinary text fields. Recognize allowed icon tokens, exact routes for built-in cards, images from `customImages`, and complete verified units from `customHtml`; keep the renderer allowlist and `skipHtml` for everything else, without `rehypeRaw`. Activity SVGs are passive, escaped, and have no external resources; do not accept arbitrary hosts or images for those cards. Do not add skill levels or tool rankings or infer work history. Content links accept HTTP/HTTPS under the web policy; `mailto:` is allowed only for Contact. Record sources and shared family marks in [third-party notices](THIRD_PARTY_NOTICES.md).
- Reserve `src/modules/` for profile sections and `src/components/ui/` for reusable visual primitives. Do not confuse product modules with generic components.
- Keep credentials and service clients in `src/server/` with `server-only`. Validate inputs at every boundary; no secret key may use `NEXT_PUBLIC_`.
- The public activity cache uses native IndexedDB with its own schema, limits, identity/scope, and original timestamps; it stores no permissions, errors, SVGs, documents, or secrets. Restoring it allows existing coverage to be used without HTTP or authorizing new queries. Freshness is 30 minutes and prior data is retained for up to 24 hours, with cleanup on access. Writes are batched asynchronously; saving is confirmed when the transaction completes. If the store fails, use RAM and show that state. Unmounting preserves the store; an explicit reset purges it and invalidates earlier work, including late reads/writes and Strict Mode work. See [ADR 0031](docs/decisions/0031-browser-persistent-activity-cache.md).
- Search prepares all 18 Extended counters and languages for the current period/filters even when no cards are selected, without changing selection or ranking. Selecting, removing, or reordering queried counters does not request data; changing scope may require different coverage. Keep limits and partiality; do not preload every year/combination or unknown resource. The browser cache and per-process RAM do not form a global cache across instances. See [ADR 0030](docs/decisions/0030-all-profile-counters-prefetch.md).
- Reuse tokens and primitives from the visual kit. Preserve keyboard navigation, labels, visible focus, contrast, and clear error states.
- The visual kit is internal: `/design-system` works only in development and must return 404 in production, with no public links. Playwright (`pnpm test:e2e:ui`) is a repository tool. Do not present Storybook as installed or add another workshop without agreeing on its dependencies.
- The editor navigation always shows sections in one horizontal row with internal scrolling, checkboxes, selection, and drag handles. Preserve focus when selecting or including a section; keep the active/focused item horizontally visible without vertical jumps; and provide left/right controls to reorder the active section. Keep drag projection temporary, confirm on drop, and use Escape to cancel. The block selector remains collapsible. Settings and preview use independent native scrolling only when there are two columns and enough height; on mobile, zoomed, or short screens, preserve natural flow. Scrollbars use design tokens and respect forced colors; do not intercept gestures or keys. Review phone viewport heights, reaching fields, and local overflow. See [ADR 0017](docs/decisions/0017-horizontal-section-navigation.md) and [ADR 0028](docs/decisions/0028-independent-editor-scroll.md).
- Prefer direct functions and components. Do not add repositories, dependency-injection containers, base classes, or layers without a concrete need. Do not add `useMemo` or `useCallback` reflexively: justify them with behavior or measurement.

Presentation typography supports only v2 `displayNameTypography?` and `headlineTypography?`, with `italic` or `monospace`; when absent, GitHub defaults apply. Derive escaped `em`/`code` under the same budget and `customHtml`, without CSS, external fonts, or Unicode substitutions in the text. Keep v1 closed and JSON portable. Full emoji examples belong only in placeholders/help text; the separate location line uses «📍 Currently based in» / «📍 Actualmente en» without changing the written or selected country.

## Verification

Use the scripts in `package.json`: `pnpm dev`, `pnpm build`, `pnpm start`, `pnpm lint`, `pnpm typecheck`, `pnpm format`, `pnpm format:check`, `pnpm docs:check`, `pnpm licenses:generate`, `pnpm licenses:check`, `pnpm test`, `pnpm test:watch`, `pnpm test:e2e`, `pnpm test:a11y`, and `pnpm check`.

Choose checks based on the change and add behavior tests when they protect relevant contracts or workflows. Do not add tests that repeat the implementation. Before finishing, review the diff, run the relevant checks, and distinguish completed results from pending verification. Do not claim that an automated review proves full accessibility.

For mobile, also check phone viewport heights, reaching the first field, and use during a long editing session. `toBeVisible()` does not guarantee that a control is inside the viewport, and Playwright may scroll it into view automatically before interacting. Take initial screenshots and reach measurements before using `scrollIntoView`, clicking, or typing into the field under evaluation. Distinguish phone emulation from testing on a physical device.

## Delegation

Roles are defined in `.codex/agents/`. Delegate only independent work with a clear goal, owned files, and acceptance criteria. Avoid parallel edits to the same files and coordinate changes to shared dependencies, configuration, and contracts. The primary agent integrates changes, reviews diffs, and validates the complete result. Read-only roles do not edit files or run actions that modify the project.

For authorized commit and push tasks, delegate to the `release` role in `.codex/agents/release.toml`, using **GPT-5.6 Luna** (`gpt-5.6-luna`, `medium` effort), per the user's explicit preference. If the delegation tool requires selecting the model separately, specify it explicitly. Do not silently substitute another model if it is unavailable. The primary agent reviews scope and checks before publication; the role retains session permissions, and this preference does not authorize commits or pushes on its own.
