# Editor de README

El editor permite crear un perfil breve con cinco secciones fijas opcionales: presentación, tecnologías, proyectos, actividad y contribuciones, y contacto. También permite agregar varias secciones personalizadas con texto, listas, enlaces, subtítulos, separadores, frases destacadas, imágenes públicas, HTML explícito y código literal. El recorrido manual funciona sin cuenta ni conexión con GitHub. Actividad ofrece diez tipos de tarjetas con datos públicos y apariencia validada; las consultas GitHub requieren configuración del servidor. Métricas no tiene sección aparte. Incluye importación local de README con revisión y respaldo antes de reemplazar, y archivos de proyecto JSON para guardar el perfil completo y retomarlo en otro momento o navegador. No hay asistencia con IA.

## Guardar y abrir proyectos

La opción **Proyecto** del encabezado permite descargar el perfil actual como `github-profile.project.json` y abrir un archivo de proyecto en otro navegador. Conserva módulos, orden, IDs, categorías, formato, fuentes HTML/código y contenido oculto. También puede guardar trabajo incompleto cuyo README todavía necesita correcciones. El JSON es una copia para continuar editando; el archivo destinado a GitHub sigue siendo `README.md`.

1. Abrí **Proyecto** y elegí **Descargar proyecto** para conservar el estado actual.
2. Usá **Abrir archivo de proyecto** para seleccionar un `.json` local UTF-8 de hasta 4 MiB.
3. Revisá el idioma del README y las secciones incluidas/ocultas. El resumen mantiene inactivo el contenido externo del archivo.
4. Continuá a confirmación, marcá la casilla y confirmá el reemplazo completo. Antes se intenta guardar un respaldo del perfil activo.
5. Para volver atrás, abrí en Proyecto el detalle del perfil anterior y elegí restaurarlo con su confirmación. También podés descargar esa copia.

Seleccionar un archivo, analizarlo o cancelar no reemplaza el borrador. Cerrar el panel o cambiar el idioma de interfaz descarta la propuesta pendiente; el perfil conserva su idioma de contenido y la interfaz su idioma actual. La apertura admite v2 y v1 estricto migrado en memoria, sin modificar el archivo original ni escribir la clave v1.

El respaldo de proyectos es independiente del perfil anterior y Markdown original del importador de README. Conserva un único perfil previo, no un historial. Si el navegador no puede guardar o encuentra datos protegidos, mantiene el perfil activo y pide una decisión explícita para continuar solo en memoria. El guardado automático permanece pausado; descargá el proyecto antes de cerrar o recargar. Un respaldo puede haberse guardado aunque la escritura del nuevo borrador haya fallado.

El contrato también limita profundidad a 32 y valores JSON a 50.000. La descarga prefiere una representación legible y usa JSON compacto cerca del límite de tamaño para permitir reabrirla, sin truncar datos. Archivos futuros, corruptos o incompatibles se rechazan sin omitir propiedades silenciosamente. Ver [ADR 0021](decisions/0021-project-files-and-recovery.md).

El perfil actual también debe caber en el formato para poder respaldarlo antes de abrir otro. Si supera sus límites, se conserva y se explica que debe reducirse antes del reemplazo. Durante la revisión, la fila de secciones permanece en su posición normal para no tapar el contenido al desplazarse. El borrador local no sincroniza ediciones entre pestañas.

## Usarlo

1. Abrí el editor en [inglés](http://127.0.0.1:3000/en/editor) o [español](http://127.0.0.1:3000/es/editor).
2. Elegí qué compartir desde la fila superior de secciones, siempre disponible. Desplazala de izquierda a derecha cuando no entren todas. Ninguna sección fija está preseleccionada ni es obligatoria. Elegir una sección sin incluir la agrega y abre su configuración; el foco permanece en su botón. Para un espacio propio, usá «Agregar sección personalizada» (el botón `+` en móvil): queda incluida y se enfoca su título opcional.
3. Usá la casilla de cada sección para incluirla u ocultarla. Conserva el foco y el contenido; no cambia por sí sola el formulario que estás configurando. La sección activa queda marcada. Las disponibles siguen al final de la fila, con un estado distinto.
4. Ordená las incluidas desde su tirador en la misma fila, usando puntero, tacto o teclado. Espacio o Enter toma y suelta; flechas izquierda/derecha mueven y Escape cancela sin guardar el orden provisional. También podés seleccionar una sección y usar las dos flechas de orden de la barra. Podés agregar y quitar entradas; al agregar se enfoca la nueva y al quitar, una vecina o una acción estable. Quitar una entrada borra esos datos del borrador.
5. Elegí el idioma del README en la cabecera de configuración, antes del título y del formulario. Solo cambia etiquetas generadas, como «Contacto» o «Proyectos»; no traduce tu texto. El selector de idioma de la interfaz es independiente.
6. Revisá la vista previa y los avisos. En pantallas amplias está a la derecha, junto a la configuración. Si hay altura suficiente, cada columna se desplaza por separado con rueda, teclado o su barra; el foco revela los campos profundos. Las barras usan el estilo del editor y respetan colores forzados. En pantallas angostas, bajas o con texto ampliado se conserva el desplazamiento natural; alterná Editar/Vista previa desde la barra superior. Cuando exista contenido visible válido, copiá el Markdown o descargá `README.md`. Ambas acciones usan el mismo contenido que la vista previa. Ver [ADR 0028](decisions/0028-independent-editor-scroll.md).
7. Para publicarlo, seguí las instrucciones de repositorio de perfil que aparecen junto a la exportación. La aplicación no publica ni modifica GitHub por vos.

Un perfil breve puede estar listo con una sola sección. No necesitás nombre, empleo, proyecto, repositorio ni actividad pública para contar algo sobre vos. La introducción permite incluir intereses, aprendizaje y actualidad sin repetirlos en formularios distintos. Un perfil sin contenido exportable mantiene deshabilitadas copia y descarga.

La fila no salta de línea al agregar secciones y sus controles tienen superficies de al menos 44 px. Los títulos largos se acotan visualmente; su nombre accesible permanece completo. El foco y la sección activa se mantienen a la vista mediante desplazamiento horizontal local. La barra superior permanece disponible al desplazarse cuando deja suficiente espacio de edición; con letra muy grande o poco alto útil deja de fijarse. El editor adapta sus columnas al espacio y a la letra. Una sección personalizada tiene un encabezado breve; su título real se conserva completo en su campo y README, además del nombre accesible y la ayuda de su botón en la fila.

«Agregar bloque» despliega las diez opciones con muestras. Empieza abierto en una sección vacía y cerrado al recuperar contenido existente; elegir una opción lo cierra y enfoca el nuevo campo. Así se puede editar lo que ya escribiste sin atravesar todas las muestras. Quitar el último bloque abre las opciones y vuelve al botón estable.

## Importar un README existente

1. Pulsá «Importar README» en la barra del editor; en móvil es el icono de archivo. Pegá Markdown o abrí un archivo `.md` UTF-8. La lectura y el análisis ocurren localmente, sin cuenta ni envío del documento a un servidor.
2. Analizá y revisá las secciones detectadas. Cada una muestra cómo quedará representada, sus avisos y sus problemas. Podés inspeccionar el original y el Markdown resultante como código: durante esta revisión no se renderizan imágenes ni HTML ni se consultan tarjetas.
3. Conservá las secciones que quieras. Si alguna tiene un problema, corregí la fuente y volvé a analizar, o excluí esa sección explícitamente. La confirmación informa las exclusiones; no se aplica una parte inválida a escondidas.
4. Revisá la confirmación y marcá que entendés el reemplazo del perfil. Antes de aplicarlo se guarda el perfil anterior completo y el Markdown original. Cerrar, volver atrás, analizar o cambiar una casilla no reemplaza el borrador.
5. El perfil importado queda abierto en el editor. Volvé a «Importar README» y desplegá el respaldo para descargar `previous-profile.json` o `imported-original.md`, o restaurar el perfil anterior con una nueva confirmación. El respaldo se conserva al restaurar.

Esta entrega crea **secciones personalizadas**, con su orden de lectura. No asigna automáticamente el contenido a presentación, tecnologías, proyectos o contacto. El README publicado no contiene las identidades, secciones ocultas ni toda la configuración del editor: importarlo no reconstruye esa información. La configuración anterior se recupera mediante el respaldo, no desde el Markdown.

Los párrafos, listas y otros contenidos sencillos se convierten a bloques visuales cuando conservan su contenido. Los bloques de código delimitados o sangrados se importan como código literal con su lenguaje cuando es representable. El formato enriquecido, tablas o listas anidadas puede convertirse a HTML permitido, con aviso. Se revisan referencias globales antes de separar secciones; un contenedor HTML que cruza límites puede mantener el documento agrupado para conservar su contexto. No se promete igualdad visual con GitHub. Los metadatos extra del código se omiten con aviso; listas de tareas y otros formatos incompatibles necesitan corrección o exclusión. Las rutas relativas y anclas deben corregirse a direcciones admitidas; no se adivina el repositorio de origen.

En README basados en HTML se detectan encabezados completos al nivel raíz y se usan para nombrar la revisión. Un nombre seguido de una frase inicial se conserva junto, aunque usen distintos niveles de encabezado. Los separadores H2 marcan la jerarquía; cuando no existen, se pueden separar por H3. Los títulos dentro de una tabla, un desplegable o un contenedor siguen dentro de ese contenido. Si no se puede separar con certeza, se conserva una sección personalizada HTML. Las imágenes de estadísticas externas permanecen como imágenes, donde las colocó el autor; no activan tarjetas ni consultas propias. Los atributos no admitidos siguen mostrando avisos.

El límite de entrada es de 100.000 unidades UTF-16 y el archivo no puede superar 400.000 bytes. También hay límites de nodos y profundidad, además de los del HTML. El archivo debe ser UTF-8; BOM y saltos CRLF se conservan en el original. Las imágenes y enlaces mantienen las políticas del editor: una URL no válida o una descripción alternativa faltante requiere revisión antes de aplicar.

Existe **un único último respaldo** de importación de README en este navegador y origen. Si el almacenamiento falla o contiene un valor protegido, la importación no se aplica automáticamente: se ofrece continuar solo en memoria mediante una acción adicional. Esa elección conserva los datos guardados y desactiva la escritura automática del perfil importado; descargá los respaldos y el proyecto antes de recargar o cerrar. No hay historial remoto. Este importador procesa Markdown; para abrir un perfil JSON usá [Guardar y abrir proyectos](#guardar-y-abrir-proyectos). Ver [decisión de importación](decisions/0018-readme-import-with-backup.md).

## Contenido y composición

- **Presentación:** nombre opcional y texto libre. Podés contar qué hacés, qué te interesa o qué estás aprendiendo. La frase de encabezado y la ubicación quedan en detalles secundarios y conservan los valores anteriores.
- **Tecnologías:** buscá por nombre o alias entre 358 herramientas, incluidos frameworks, ORMs, bases de datos, mensajería, infraestructura e IA. Elegí categorías sugeridas o un destino existente; las nuevas selecciones aparecen como chips con icono y nombre. También podés agregar texto propio sin icono. Flechas, Enter y Escape permiten operar las sugerencias con teclado; las herramientas ya elegidas no se agregan otra vez. Los detalles secundarios permiten crear, renombrar y ordenar categorías, mover y ordenar herramientas y editar notas opcionales. Quitar una categoría elimina su título y conserva las herramientas. Recuperar un borrador o cambiar idioma no reorganiza datos; «Organizar por categoría» es una acción explícita que confirma el reemplazo de títulos existentes.
- **Proyectos:** nombre, descripción, participación, tecnologías y enlaces opcionales. Las tecnologías se agregan como campos de texto, sin exigir un repositorio.
- **Actividad y contribuciones:** descripción manual de aportes, revisiones, documentación o comunidad, con título y enlace opcionales. El bloque plegable permite consultar un usuario público, elegir entre diez tipos de tarjetas locales, configurar apariencia y opciones Extended y seleccionar sugerencias de aportes. Ninguna tarjeta está activada al empezar y no hace falta usuario para contar un aporte manual.
- **Contacto:** pulsá «Agregar red social» para crear una entrada y elegí dentro el servicio, portfolio/web propia o correo; luego completá su URL. El selector recibe el foco al agregar y Tab permite avanzar a la dirección. Podés repetir servicios y webs propias, cada uno con URL y nombre independientes. La etiqueta personalizada sigue en detalles opcionales. El catálogo incluye LinkedIn, LeetCode, HackerRank, YouTube, Facebook, Instagram, GitHub, X, Bluesky, DEV Community, Medium, Twitch y Stack Overflow. Cambiar el servicio sugerido no reemplaza la dirección ni el nombre. El icono sigue al dominio validado de la URL; las webs propias y el correo conservan un icono genérico en el formulario y enlaces de texto en el README.

En los detalles opcionales de presentación, Ubicación permite buscar un país por nombre en inglés, español o código de dos letras. Elegir una sugerencia completa el nombre y agrega su bandera. El catálogo incluye 249 países y territorios, con imágenes locales para evitar depender del soporte de emoji del sistema. Podés usar flechas y Enter, cerrar con Escape, o escribir libremente una ciudad o zona horaria sin elegir país. No se detecta tu ubicación ni se modifica texto guardado anteriormente. Cambiar de idioma de interfaz conserva el nombre elegido.

Una sección visible vacía no agrega títulos sin contenido. Un grupo tecnológico sin entradas exportables se omite, aunque tenga nombre. El contenido parcial útil se muestra sin inventar los datos que faltan.

### Secciones personalizadas

Podés agregar varias secciones propias y ordenarlas entre las fijas. Cada una acepta un título opcional y diez opciones para agregar contenido: texto, lista con puntos (•), lista numerada (1., 2., 3.), enlace web, subtítulo, separador, frase destacada, imagen/banner, HTML y código. El selector muestra pequeñas muestras locales decorativas para anticipar su distribución, con nombre y descripción accesibles en ambos idiomas. Los bloques se agregan sin texto ni imágenes de ejemplo. Los puntos y números de listas se agregan automáticamente: cada campo recibe solo el texto de un elemento. Los títulos repetidos son válidos; la navegación identifica cada instancia sin modificar el texto que aparece en el README. Sin título se exporta el cuerpo; un título sin contenido útil no genera un encabezado vacío.

Los botones de agregar contenido se operan con teclado y enfocan la nueva entrada; el separador, que no tiene campos, enfoca su encabezado. Las flechas permiten ordenar los bloques y sus acciones de quitar borran únicamente ese contenido, conservando un destino de foco para continuar. Agregar, quitar y mover se anuncian en inglés y español. Los enlaces aceptan `http://` y `https://`, con etiqueta opcional; `mailto:` sigue disponible únicamente en Contacto.

El subtítulo crea un encabezado menor dentro de una sección con título (`###`); si no hay título de sección, usa `##` para no saltar esa jerarquía. El separador genera una línea horizontal (`---`). La frase destacada usa una cita Markdown (`>`) y conserva dentro de ella las líneas y párrafos escritos. Escribir HTML o Markdown en esos campos sigue produciendo texto escapado.

En un bloque de texto propio, comenzar la primera línea con `- ` lo convierte en una lista con puntos (•). Enter agrega un ítem; en el último ítem vacío termina la lista y permite seguir con texto. Pegar varias líneas crea varios ítems. «Convertir a texto» conserva el contenido y sus marcadores. Estas ayudas se aplican solo a secciones personalizadas: presentación, notas y campos fijos no interpretan listas ni Markdown libre.

«Duplicar sección» crea una copia independiente de título, bloques, ítems, orden e inclusión, con identidades nuevas. Editar o eliminar esa copia no modifica el original. Ocultar una sección conserva todos sus datos y su posición; «Eliminar sección» borra solo esa instancia y su referencia. Si contiene título o contenido, se pide confirmación; una sección vacía puede quitarse directamente. Después se enfoca una sección vecina o el panel para continuar.

### Imágenes y banners propios

Elegí «Agregar imagen / banner» y completá:

- **URL pública de la imagen:** una dirección HTTPS directa a un recurso ya alojado, visible sin iniciar sesión. Se admiten query y direcciones sin extensión de archivo; no se verifica el formato real del recurso.
- **Descripción de la imagen:** texto alternativo que cuenta qué muestra. Es necesario para exportar una imagen con URL y no se interpreta como HTML o Markdown.

La política acepta dominios con sintaxis pública y rechaza direcciones IP, hosts locales o privados conocidos, credenciales, fragmentos y puertos no estándar. La validación es sintáctica: no consulta DNS, no solicita la imagen para comprobarla y no garantiza disponibilidad. Una URL inválida o una descripción sin URL señala el campo de dirección; una URL sin descripción señala el texto alternativo. Una imagen completamente vacía se omite. Los errores de una sección oculta no bloquean el README.

La aplicación no sube archivos ni aloja las imágenes propias. Una ruta del equipo, `blob:`, `data:`, `assets/banner.png` o elegir un archivo local no genera una dirección exportable. Para usar una imagen del repositorio, primero publicala y obtené una URL HTTPS directa que cumpla la política. El archivo debe seguir disponible para que GitHub lo muestre; copiar o descargar el README no copia el recurso.

La vista previa carga la imagen directamente desde su host en el navegador, con carga diferida, decodificación asíncrona y sin enviar referrer. No usa proxy ni optimizador del servidor. Si falla la carga, muestra la descripción y un enlace para abrir la dirección. Ese estado es temporal y no modifica el borrador, el Markdown ni la posibilidad de exportar una dirección admitida. No equivale a comprobar que la imagen esté disponible para otras personas. Ver [ADR 0014](decisions/0014-custom-visual-blocks.md).

### HTML explícito

Agregá el bloque HTML de una sección personalizada para escribir o pegar un fragmento de perfil. Permite, por ejemplo, centrar una presentación, poner imágenes enlazadas en una fila, armar una tabla breve o usar un desplegable. El campo conserva el código original exactamente; el borrador no se reemplaza con el resultado filtrado.

La guía plegable explica el formato admitido y ofrece tres ejemplos: encabezado centrado, tabla y desplegable. Solo se insertan al elegir uno; si el campo ya contiene código, se confirma su reemplazo. Las muestras del selector son locales y decorativas. Ningún ejemplo se agrega al crear el bloque.

El análisis muestra avisos cuando retira etiquetas, atributos o comentarios, o repara HTML mal formado. Podés desplegar el HTML exportado para inspeccionar qué se copiará o descargará. Puede representar los saltos de línea con entidades HTML para conservarlos sin activar Markdown; tu código original mantiene sus líneas. Un aviso por filtrado no equivale a un error; una URL no admitida, imagen sin atributo `alt`, estructura inválida o contenido que exceda los límites señala el campo de código e impide exportar una sección visible. Una fuente vacía se omite; una fuente no vacía que queda sin contenido útil requiere corrección. Ocultar conserva el código y excluye sus errores del README.

| Contenido                           | Formato admitido                                                                                                               |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Encabezados y distribución sencilla | `h1`–`h6`, `p`, `div`, `span`, `br`, `hr`; `align="left"`, `"center"` o `"right"` en los elementos admitidos.                  |
| Texto                               | Negrita, énfasis, tachado, subíndice, superíndice, `kbd`, citas y `pre`/`code`.                                                |
| Listas y tablas                     | `ul`/`ol`/`li` y tablas con filas, celdas, encabezados y título; spans de celdas acotados.                                     |
| Desplegables                        | `details` con un único `summary` al principio y texto que lo identifique; `open` permite abrirlo inicialmente.                 |
| Enlaces                             | `a` con destino HTTP/HTTPS absoluto y nombre accesible; un `aria-label` puede identificar un enlace cuyo contenido no lo haga. |
| Imágenes                            | `img` con URL HTTPS pública y atributo `alt` presente. `alt=""` es una elección explícita para imágenes decorativas.           |

Las dimensiones de imagen admiten entre 1 y 2.000 píxeles; `width` admite además porcentajes entre 1 y 100 %. No hay CSS propio, JavaScript, eventos, formularios, iframes, clases o identificadores; tampoco `srcset`, `picture` ni SVG inline. Los atributos no admitidos se filtran. Una URL a un SVG público mediante `img` sigue siendo una imagen externa sujeta a la política HTTPS, sin habilitar SVG inline.

Las rutas relativas, direcciones locales y `#anclas` requieren adaptación explícita; nunca se resuelven contra el dominio del editor. `mailto:` continúa reservado a Contacto. Las imágenes no se suben ni se comprueban desde el servidor: usan la misma política sintáctica de dominio público y carga directa del navegador que el bloque de imagen. En HTML, la ausencia de `alt` es un error; dejarlo vacío explícitamente tiene un significado decorativo distinto.

Cada bloque tiene un límite de 30.000 unidades UTF-16 de fuente, 1.500 nodos y profundidad 32. El conjunto de HTML de secciones visibles admite 150.000 unidades de fuente. El contador usa la longitud de una cadena JavaScript: algunos emojis ocupan dos unidades. Los límites se aplican al análisis de exportación y no recortan el código guardado.

El HTML del bloque no interpreta Markdown: escribí `<strong>texto</strong>` para negrita, no `**texto**`. No es una página HTML completa, React o MDX, ni un importador de README. Los niveles h1–h6 se conservan al exportar; la vista previa adapta su nivel semántico al encabezado de la sección para integrarlos en la página del editor. GitHub aplica sanitización y estilos propios, por lo que la vista previa es aproximada. Ver [ADR 0015](decisions/0015-explicit-profile-html.md).

### Entender las categorías de tecnologías

«Organizar nuevas herramientas» permite elegir categorías automáticas, una categoría existente o ninguna. En automático, cada herramienta usa una sugerencia según su función: React va a Frontend y Docker a Cloud y DevOps; los nombres propios no reconocidos van sin categoría. Si elegís una categoría propia, todas las nuevas herramientas van allí. La ayuda cambia con la elección y cada resultado de búsqueda indica el destino real antes de agregarlo. El anuncio de alta confirma ese destino.

«Ver las 9 categorías sugeridas» abre una guía con los nombres y ejemplos del catálogo: lenguajes; frontend; backend; móvil y escritorio; datos y mensajería; cloud y DevOps; testing y calidad; IA y automatización; herramientas y diseño. Abrirla no crea grupos ni modifica el perfil. Estas opciones afectan solo a nuevas herramientas; las guardadas conservan su lugar. Para reorganizar las existentes, usá la acción explícita «Organizar por categoría» en los detalles de categorías.

La navegación muestra primero las secciones incluidas, en el orden del README, y luego las ocultas. El formulario y el selector de idioma permanecen en el mismo panel al cambiar de sección. Solo el formulario activo está montado; no hay una lista de formularios desplegables. La navegación, el encabezado del formulario y el indicador de la vista previa identifican la sección en edición. Ese indicador no modifica ni resalta un fragmento del Markdown exportado.

**Configurar** selecciona el formulario; **ocultar** excluye la sección del README y conserva sus datos; **quitar una entrada** borra esa entrada. Las casillas no cambian el formulario activo: si ocultás la sección que estás configurando, sus datos siguen editables y la interfaz indica que está oculta. Agregar y editar una sección oculta cambia explícitamente su inclusión. La selección activa, el despliegue de navegación móvil y la vista Editar/Vista previa son estado de interfaz, fuera del documento guardado.

Solo las secciones incluidas tienen tirador. Arrastrar permite mover una sección fija o personalizada por encima o debajo de otras; Subir/Bajar mueve una posición visible. `sectionOrder` conserva las nueve referencias fijas y una por cada instancia propia. Al reordenar las incluidas, las referencias ocultas, retiradas y de métricas permanecen en sus espacios. Ocultar y volver a mostrar una sección no reinicia su posición. El cambio de orden se guarda al terminar un movimiento válido; cancelar el arrastre conserva el orden anterior y no escribe otro documento.

El tirador es el único punto que inicia el arrastre. Los nombres de sección, las casillas y los campos mantienen su interacción propia. El gesto táctil fuera del tirador conserva el desplazamiento de la página. Las instrucciones y los anuncios de posición están disponibles en inglés y español; los botones Subir/Bajar ofrecen una alternativa al arrastre y distinguen sus extremos.

Las secciones con enlaces, direcciones de imagen, descripciones alternativas o HTML inválidos muestran un aviso textual. Su acción de revisión selecciona el formulario, vuelve a la vista de edición cuando corresponda y lleva al campo inválido; el error no depende solo del color. Los botones Editar/Vista previa comunican cuál está activo mediante `aria-pressed`.

## Actividad y contribuciones

Podés completar únicamente un aporte manual. Si querés sumar información de GitHub, abrí el bloque opcional, ingresá el usuario y pulsá la consulta de actividad pública. Escribir un usuario, abrir el bloque o recuperar el borrador no dispara la consulta del formulario. Las tarjetas previamente seleccionadas sí vuelven a cargar su imagen cuando se muestran, como también ocurrirá en GitHub.

Podés elegir independientemente las tarjetas de perfil y consultar sus datos públicos:

- **Calendario:** contribuciones diarias del período indicado, hasta 365 días, sin rachas ni calificación.
- **Resumen:** commits, pull requests, issues y revisiones del mismo período. Su suma no tiene por qué coincidir con el calendario, que puede incluir otros tipos.
- **Lenguajes:** proporción de bytes en los repositorios públicos propios analizados, excluyendo forks. Son datos de código actual, sin limitarse al período del calendario ni representar conocimientos. Se aclaran alcance y muestra parcial cuando hay límites de consulta.
- **Panorama de actividad:** composición de calendario, resumen y lenguajes, con notas que distinguen el período de contribuciones y la muestra de código actual.
- **Actividad por mes:** suma de las contribuciones diarias agrupadas por mes UTC; los meses que no están completos en el período se identifican como parciales.
- **Resumen de actividad Extended:** elegí y ordená entre 18 contadores públicos de actividad, estrellas, seguidores, PR, issues, discusiones y repositorios con aportes. Los valores indican su alcance temporal y si son parciales. Podés filtrar por repositorio, propietario, rol y exclusiones, elegir commits del período/año/histórico e incluir repositorios propios en los contadores correspondientes.
- **Lenguajes de repositorios Extended:** cinco diseños, de 1 a 20 lenguajes, ocultamiento de lenguajes, barras o valores, bytes/porcentajes y pesos de bytes/cantidad de repositorios. Un porcentaje ponderado describe la fórmula elegida, sin convertirse en una medida de conocimientos.
- **Repositorio Extended:** agregá hasta doce destinos `owner/name` públicos. Podés mostrar propietario, acotar líneas de descripción y consultar cinco contadores públicos de PR/issues de un usuario explícito en ese repositorio.
- **Gist Extended:** agregá hasta doce IDs de Gists públicos. Muestra metadatos, estrellas, forks y lenguaje disponible. El contenido de archivos que pueda venir incrustado en la respuesta REST se descarta; no se consulta raw_url ni se muestra o guarda esa fuente. Los Gists secretos quedan excluidos aunque conozcas su ID.
- **WakaTime Extended:** ingresá un usuario WakaTime independiente del de GitHub, con actividad y lenguajes publicados. Muestra los últimos siete días, tiempo o porcentaje, de 1 a 20 lenguajes, barra opcional y diseño normal/compacto. No pide claves WakaTime ni envía el token GitHub a ese proveedor.

La apariencia permite elegir tema claro/oscuro, tres paletas, tres diseños propios y ancho compacto/amplio, además de 79 temas nombrados de Extended. Colores hexadecimales y degradados validados, título, borde, iconos, negrita y formato numérico permiten personalizarla sin CSS libre. El ancho explícito admite de 700 a 1200, el radio de 0 a 30 y la interlínea de 22 a 50. Las muestras de diseño son locales y decorativas: no consultan GitHub ni agregan datos al perfil. Restablecer elimina solo la apariencia y conserva usuarios, destinos, tarjetas, opciones de datos y aportes. No se agregan valores por defecto al recuperar un borrador. El tema elegido para las tarjetas es independiente del editor y se aplica a todas las seleccionadas.

El ranking Extended empieza desactivado. Al elegirlo podés mostrar letra, índice porcentual de la fórmula o icono; usa commits, PR, issues, revisiones, estrellas y seguidores. No mide habilidad ni un percentil de población observado y se oculta si una entrada falta o es parcial. Las tarjetas conservan la licencia MIT y los avisos del código adaptado y se generan en este servidor, sin llamar al servicio alojado de Extended. La [matriz de compatibilidad](github-stats-extended.md) explica coberturas, límites y diferencias del origen; la decisión está en [ADR 0024](decisions/0024-extended-public-suite-and-mit.md).

Ingresá tu usuario y pulsá «Buscar datos», justo debajo del campo, antes de elegir tarjetas. La acción está disponible sin ninguna tarjeta seleccionada. Las miniaturas de elección son esquemas locales decorativos, sin datos de tu cuenta ni consultas. También se puede seleccionar antes de buscar. La búsqueda opcional de aportes para destacar tiene otro botón y no es requisito para cargar tarjetas.

La primera búsqueda carga el snapshot básico, los 18 contadores Extended y los lenguajes para el período y los filtros actuales, mediante dos JSON, además de los recursos específicos ya seleccionados que falten. Las cinco tarjetas propias comparten la fuente básica. La configuración se respeta aunque no haya tarjetas elegidas. Se incluyen los contadores históricos con sus límites de años y paginación; no se precargan todas las combinaciones de años/filtros ni destinos desconocidos. El progreso y los errores se muestran incluso sin tarjetas; los resultados independientes aparecen sin esperar al resto y los errores no se convierten en ceros. Ver [ADR 0030](decisions/0030-all-profile-counters-prefetch.md).

Los datos se conservan temporalmente en IndexedDB de este navegador, con frescura de hasta 30 minutos desde su consulta original. Después de Buscar, elegir tarjetas o personalizar opciones cubiertas las muestra sin nuevas peticiones de SVG o JSON. Recargar restaura los datos disponibles sin consultar; no reactiva permisos de red. Si faltan datos o vencieron, se requiere Buscar en la sesión recuperada. Después de una búsqueda explícita, nuevos alcances pueden consultar faltantes agrupando cambios durante 300 ms. Los recursos válidos aplicados y seleccionados también pueden cargarse tras Buscar. Cambiar de formulario o desmontar conserva la caché; reemplazar/importar/restaurar el perfil o borrar el README la purga y cancela respuestas anteriores. El Markdown mantiene sus URLs públicas y nunca guarda snapshots. Ver [ADR 0029](decisions/0029-account-first-activity-search.md), [ADR 0030](decisions/0030-all-profile-counters-prefetch.md) y [ADR 0031](decisions/0031-browser-persistent-activity-cache.md).

La lista de sugerencias contiene PR e issues públicos del período. Elegir uno agrega un aporte editable con título, enlace y espacio para una nota propia. No se agregan automáticamente; una URL ya elegida no se duplica. Podés mantener, editar o quitar esos aportes aunque después cambies el usuario de consulta.

Usuario inválido, perfil no encontrado, servidor no configurado, cuota agotada e indisponibilidad tienen mensajes distintos. Cero actividad es un resultado válido y no un error. Si falla una actualización del mismo usuario, el último resultado válido puede seguir visible con fecha y aviso; no se inventan ceros ni ejemplos. Cambiar usuario descarta el resultado anterior y las respuestas tardías no pueden reemplazarlo.

La caché de tarjetas usa un formato versionado separado del borrador localStorage y del documento. Valida datos públicos, identidad, filtros, períodos y fechas al recuperarlos; no guarda errores, permisos, credenciales, SVG ni Blob URLs. Los datos anteriores pueden mostrarse hasta 24 horas con aviso, sin rejuvenecer su fecha. La limpieza se aplica al acceder o guardar. El estado indica revisando, guardando, guardado o uso exclusivo de RAM si IndexedDB no está disponible. No se guarda el perfil en esa base ni se sincroniza entre navegadores/dispositivos. La búsqueda opcional de sugerencias mantiene su propio estado de formulario. En el perfil se guardan usuarios y destinos públicos, tarjetas, apariencia, opciones Extended y aportes seleccionados o escritos. Estos aportes permiten agregar contexto con título, descripción y enlace dentro del README; no se publican en una tarjeta dinámica ni en URLs con su texto. Las selecciones de tarjetas de un borrador anterior pueden desmarcarse aunque el servidor no pueda consultarlas. La muestra GitHub y el histórico tienen límites declarados; WakaTime indica últimos siete días sin inventar fechas si el proveedor no las entrega.

La aplicación aloja las tarjetas como SVG propios y pasivos. Para exportarlas necesita un origen público HTTPS configurado por quien opera el servidor; GitHub no puede acceder a un servidor local. Sin ese origen, búsqueda y vista previa funcionan localmente. El aviso se ubica junto a copia y descarga, que siguen deshabilitadas mientras haya tarjetas seleccionadas. Excluirlas conserva su configuración y permite exportar los aportes manuales. No se pide a quien crea un perfil que ingrese tokens ni configure servicios.

Que una tarjeta se dibuje en el editor no demuestra que GitHub pueda cargarla: la vista previa usa datos temporales del navegador. En Vercel Production, el servidor puede resolver el dominio estable del proyecto cuando no hay `APP_URL`; en local y Preview se mantiene el origen explícito. El aviso explica esa diferencia y recuerda que el proyecto JSON sigue disponible para conservar todo. Los aportes manuales sin tarjetas no requieren origen ni usuario de GitHub. Ver [configuración de alojamiento](vercel-deployment.md#3-variables-por-entorno).

Las imágenes del README se actualizan según la caché del servicio, no son capturas almacenadas en el documento. La fecha de actualización y el período pertenecen a los datos consultados; un fallo no convierte un gráfico anterior en actividad nueva. La consulta pública debe ser habilitada por la persona que administra el despliegue, según [ADR 0010](decisions/0010-github-activity.md).

El botón limita las consultas durante la edición. Las tarjetas publicadas conservan URLs dinámicas públicas y pueden consumir cuota al renovarse. La [guía de API, credenciales y alojamiento](github-api-and-hosting.md) explica el PAT compartido, las cachés y los límites de Vercel Hobby para quien administre el servidor.

## Texto y enlaces admitidos

Los campos ordinarios se interpretan como **texto plano**: escribir Markdown o HTML no habilita formato libre. El generador escapa esos caracteres. La excepción es el bloque HTML explícito, que analiza y filtra su fuente antes de generar la salida. La vista previa renderiza el mismo Markdown mediante ReactMarkdown 10.1, sin parseo global de HTML ni plugins GFM y con elementos permitidos explícitos. Las fuentes, colores y distribución del editor no se incrustan en el README; su apariencia final depende de GitHub.

Las tecnologías reconocidas se exportan con un icono decorativo de 20 × 20 y su nombre visible escapado. El generador construye las etiquetas `img` exclusivamente desde el catálogo curado, con URLs fijadas de Devicon, Simple Icons y Lobe Icons. Los nombres propios siguen como texto; las notas se conservan como texto escapado. Los títulos de categoría se exportan cuando tienen contenido. La vista previa respeta el orden y permite saltos de línea; sigue aceptando los tokens anteriores de 32 × 32. No se agrega CSS al README.

Los contactos reconocidos agregan dentro del enlace un icono de 20 × 20, construido desde su catálogo de Simple Icons. El icono tiene `alt=""` porque el texto visible ya nombra el enlace; no duplica su nombre accesible. La URL validada determina el servicio por dominios explícitos: una etiqueta «LinkedIn» en una web propia no le asigna su marca. No se admiten URLs de iconos personalizadas.

Una selección de país agrega una bandera decorativa de 20 × 15 desde el catálogo de flag-icons, junto al nombre legible del país. Se admite únicamente su marcado generado exacto y URL fijada; la vista previa resuelve el SVG local equivalente. Las ubicaciones libres, incluso texto propio con emoji de bandera, conservan su texto y no se convierten en imágenes.

La vista previa convierte tokens exactos de iconos en nodos de imagen y verifica URL permitida y alternativa vacía para tecnología/contacto; los tokens tecnológicos anteriores requieren además el nombre alternativo correcto. Resuelve solo los SVG locales equivalentes. Admite también las rutas exactas de tarjetas de actividad generadas por la aplicación, con origen configurado y parámetros permitidos; las resuelve contra el servidor local para revisar el mismo Markdown. Para bloques de imagen exige coincidencia exacta de URL y alternativa con `customImages`, metadatos del mismo resultado del generador, y vuelve a comprobar la política HTTPS. Las unidades de HTML se reconocen únicamente mediante rangos y contenido exactos de `customHtml` y se muestran con elementos React permitidos. No persiste esos metadatos ni interpreta imágenes escritas en otros campos. `skipHtml` sigue activo para cualquier otro HTML; no se usa `rehypeRaw` ni `dangerouslySetInnerHTML`. Los assets, licencias MIT/CC0 y atribución se incluyen en [recursos de terceros](../THIRD_PARTY_NOTICES.md), con sus fuentes fijadas. Algunas herramientas usan una marca de familia documentada. Los iconos de terceros dependen de sus URLs originales en GitHub; las tarjetas dependen del despliegue de esta aplicación; las imágenes propias, del host elegido.

Los enlaces web de proyectos, contribuciones, contacto y secciones personalizadas admiten URLs absolutas `http://` o `https://`, sin credenciales, espacios, controles ni barras invertidas. Ejemplo: `https://example.com/portfolio`.

Solo contacto admite además `mailto:` con un solo buzón ASCII y dominio con al menos dos partes, sin listas, parámetros, fragmentos ni contenido codificado. Ejemplo: `mailto:alex@example.com`.

No se admiten rutas relativas, URLs que comienzan con `//`, `javascript:`, `data:`, enlaces con usuario/contraseña ni un `mailto:` con asunto o cuerpo. Un enlace inválido en cualquier sección activa y visible, incluidas las propias, bloquea la exportación y muestra el error junto a su campo. Los datos de secciones ocultas o retiradas no se exportan ni bloquean la salida.

Un enlace opcional vacío no exige completarlo. Las filas de contacto o enlaces de proyectos completamente vacías se omiten. Si tienen etiqueta pero no una URL admitida, requieren corrección. Una URL válida sin etiqueta usa el nombre del servicio reconocido en contacto, o la dirección en los demás casos. Un enlace inválido bloquea toda la salida, sin producir un README parcial silenciosamente.

## Guardado y recuperación

El borrador se guarda en este navegador, bajo el mismo origen, sin enviar el documento completo a un servidor. Las consultas de actividad envían el usuario y las opciones públicas elegidas; las URLs de tarjetas incluyen tipo, identificador público, idioma y opciones validadas de apariencia/datos. No contienen tokens ni los aportes manuales. Las imágenes propias se solicitan al host indicado desde el navegador al mostrarse; no se suben ni copian al guardar el borrador. La lectura del borrador se valida antes de habilitar el guardado automático. Después de editar hay una espera de 500 ms; se intenta guardar también al ocultar o abandonar la página. El estado visible permite distinguir guardado correcto de una dificultad para guardar.

Si el borrador está dañado, es incompatible o no se puede leer, no se reemplaza automáticamente. Se puede trabajar en memoria; iniciar un borrador nuevo requiere confirmación para permitir el reemplazo. Cancelar esa confirmación conserva el valor existente. Si falla una escritura por cuota o restricciones del navegador, el aviso permanece: se puede seguir editando y exportando un README válido, pero los últimos cambios pueden perderse al salir.

El trabajo en memoria se conserva al cambiar el idioma de la interfaz dentro de la misma pestaña, incluido el idioma del README y el estado del error. Esta recuperación temporal no sobrevive a una recarga completa ni al cierre de la pestaña: si el guardado falla, descargá el README antes de recargar o cerrar.

No hay sincronización entre dispositivos, copia de seguridad remota ni historial. El importador de README ofrece un último respaldo local descargable y restaurable. [Proyecto](#guardar-y-abrir-proyectos) permite descargar y abrir el perfil JSON completo, con su propio respaldo independiente, para continuar la edición en otro navegador o dispositivo. Cambiar host, puerto o protocolo usa otro almacenamiento; ver [guía operativa](development.md). Un cierre abrupto puede impedir guardar los últimos cambios.

## Compatibilidad del documento

El formato actual es `ProfileDocument` v2, guardado en `github-profile-generator.profile.v2`. Conserva datos ocultos, IDs opacos, idioma, configuración de métricas y las estructuras fijas heredadas. `sectionOrder` mezcla referencias fijas y propias; `customSections` contiene sus bloques. Los tipos visuales, HTML, código y las opciones de formato amplían v2 sin cambiar claves ni agregar propiedades por defecto a los bloques anteriores. Un lector antiguo estricto puede rechazar esos tipos y debe conservar el valor incompatible. Las tecnologías siguen guardándose como nombres y contextos en sus grupos existentes; las nuevas altas comienzan con contexto vacío. Las URLs de imágenes propias y la fuente HTML pertenecen a sus bloques; no se guardan URLs de iconos, `customImages`, `customHtml` ni el árbol analizado. La fuente HTML original se conserva al duplicar, ocultar, cambiar idioma o recuperar.

Si falta v2, se busca `github-profile-generator.profile.v1`, se valida y se migra en memoria. La migración conserva contenido, flags y orden, no agrega secciones propias ni modifica el original v1. Abrir, recuperar o cambiar el idioma no guarda la migración: la primera edición escribe la clave v2 y deja v1 intacta como original local. Esto no proporciona sincronización ni una copia remota de seguridad.

Si v2 existe pero es inválido o no se puede leer, no se usa v1 para sustituirlo automáticamente. Se conserva el valor problemático y continúa disponible el recorrido en memoria; iniciar otro borrador requiere la confirmación existente. Cancelar mantiene ambos originales. Las escrituras actuales y el reinicio confirmado afectan a v2, sin eliminar la clave v1.

Conocimientos, formación y actualidad están retirados. No tienen navegación, formulario ni salida, aunque el borrador tenga contenido o visibilidad en esos IDs. Sus estructuras internas se conservan sin editarlas, borrarlas ni fusionarlas con presentación. Un enlace inválido guardado allí no impide exportar las cinco secciones activas. Esta conservación interna no es una opción para habilitar los módulos retirados.

Contribuciones y métricas se presentan como una única sección incluida cuando cualquiera de sus flags heredados es verdadero. No se cambian los flags al recuperar. La casilla global al ocultar apaga ambos y conserva datos; al volver a mostrar activa contribuciones y métricas solo si quedan tarjetas seleccionadas. Los aportes manuales respetan su flag; las tarjetas respetan el de métricas. El generador usa siempre la referencia `contributions`, omite la salida independiente de `metrics` y evita encabezados duplicados. Reordenar conserva la referencia interna de métricas y las demás posiciones ocultas.

El contrato y la API se describen en [modelo del perfil](profile-model.md). Las instancias propias y la migración se registran en [ADR 0013](decisions/0013-custom-sections.md), ampliado por [ADR 0014](decisions/0014-custom-visual-blocks.md) para los bloques visuales e imágenes y por [ADR 0015](decisions/0015-explicit-profile-html.md) para HTML explícito; el retiro de módulos, en [ADR 0008](decisions/0008-focused-profile.md); los catálogos, en [ADR 0009](decisions/0009-profile-icons.md); la actividad unificada, en [ADR 0010](decisions/0010-github-activity.md). Los ADR anteriores conservan su contexto histórico.

## Código y formato en secciones personalizadas

«Agregar código» crea un bloque vacío. Pegá la fuente y elegí un lenguaje sugerido (TOML, JSON, JavaScript, Python, entre otros), escribí un identificador propio o dejalo vacío para texto simple. La muestra JSON se inserta solo al elegirla; reemplazar código existente requiere confirmación. La fuente es literal: escribir etiquetas, scripts, imágenes o Markdown no los ejecuta ni carga sus recursos.

HTML y código comparten un editor con colores, números de línea y ajuste de líneas. Carga bajo demanda y permite usar «Texto simple» si se prefiere. Tab y Shift+Tab entran y salen del campo; los botones de sangría y Ctrl+] / Ctrl+[ (Cmd en macOS) modifican la selección. Los ejemplos y cambios de modo no formatean automáticamente la fuente. Todos los lenguajes sugeridos tienen resaltado local, incluidos C#, Java, PHP y Markdown. Un identificador propio desconocido sigue editable como texto y muestra una ayuda específica. GraphQL ofrece resaltado léxico. No valida la corrección del programa ni ejecuta código.

El código admite hasta 30.000 unidades UTF-16 por bloque y 150.000 entre los bloques visibles. Un lenguaje inválido o un exceso muestra el error junto al campo y bloquea copia/descarga hasta corregirlo u ocultar esa sección. Duplicar conserva fuente y opciones con identidades independientes. Los delimitadores Markdown se eligen para que los backticks escritos dentro no puedan cerrar el bloque. La vista previa muestra la fuente literal del mismo Markdown generado, con resaltado opcional y una acción para copiar solo ese fragmento, sin incluir controles en el README.

En «Formato del título» podés elegir nivel 1, 2 o 3 y alineación izquierda, centro o derecha para el título propio. Los párrafos y subtítulos tienen controles plegables de formato y pueden convertirse entre texto y encabezado conservando su identidad y contenido. La alineación afecta solo al texto seleccionado; no centra listas, imágenes o código. La configuración inicial conserva la salida previa: no se agregan propiedades al recuperar documentos antiguos.

Los niveles se exportan con Markdown. El centrado y la alineación derecha generan HTML permitido, escapando el texto y respetando los límites de HTML existentes. Escribir HTML en un párrafo sigue siendo texto literal. No hay formato inline libre, CSS, fuentes ni colores personalizados; la apariencia final depende de GitHub. La vista previa adapta la jerarquía de encabezados al editor sin cambiar la salida. Ver [decisión de código y formato](decisions/0019-code-and-formatting.md).

## Formato de Presentación

Abrí «Formato visual» debajo de los campos de Presentación. El nombre y la frase pueden usar H1, H2 o H3 y alineación izquierda, centro o derecha. El texto Sobre vos y la ubicación tienen alineación independiente. Podés centrar el nombre y mantener el resto a la izquierda, o elegir otra combinación. Las opciones no exigen completar campos vacíos ni convierten el perfil en un CV.

La vista previa, copia y descarga usan la misma salida. Las banderas elegidas conservan sus iconos locales en la vista previa; escribir etiquetas en el texto sigue siendo literal. «Restablecer formato de presentación» conserva los textos. Abrir un borrador previo mantiene su formato y no agrega opciones por defecto. Ver [decisión de Presentación](decisions/0020-presentation-formatting.md).

## Borrar el README actual

«Borrar README» está junto al estado de guardado; en móvil usa el icono de papelera con ese nombre accesible. La confirmación explica que se vacían todas las secciones y datos del perfil actual, incluidos los ocultos y las tarjetas seleccionadas. Cancelar conserva contenido y foco. Confirmar empieza un perfil vacío con el mismo idioma del README y deshabilita exportación hasta agregar contenido.

El borrado conserva la clave v1 original y el último respaldo de importación. No es una purga del almacenamiento ni del texto temporal del importador. El guardado de un borrador sano se confirma antes de informar éxito. Si el navegador falla o el valor guardado está protegido, el perfil se vacía solo en memoria y se explica que recargar puede recuperar el anterior. La acción invalida los guardados pendientes para que no vuelvan a escribir el contenido borrado.
