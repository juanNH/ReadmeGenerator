# Product

GitHub Profile Generator helps you create a short personal GitHub README: write an introduction, choose technologies, and share projects, contributions or links. The flow supports a short, informal profile without requiring a résumé structure.

## People and principles

The same editor works for people with little public activity, people who work in private repositories and regular contributors. It does not infer skills from commits, stars or detected languages. The optional Extended activity ranking starts disabled and explains that its formula measures neither skill nor an observed population percentile.

Every section is optional. The manual flow works without an account or a connection to GitHub. An introduction can mention interests, learning or current activity without repeating them in other forms. Adding a technology does not require an explanation of how you use it. Hiding a section preserves its data; removing an entry deletes it through an explicit action.

A short profile can be complete. The app does not show a completion percentage or require a job, projects, metrics or contact details. English is the initial interface language, with Spanish available as well; controls are recognizable and keyboard alternatives are available for dragging.

## The five fixed sections

| Section                    | Content                                                                                                  |
| -------------------------- | -------------------------------------------------------------------------------------------------------- |
| Introduction               | Optional name and free-form text; a headline and location are secondary details.                         |
| Technologies               | Search by name or alias, select tools with icons, remove them as chips, or enter custom text.            |
| Projects                   | Name, description, your contribution, technologies and optional links; GitHub is not required.           |
| Activity and contributions | Manual contributions with optional titles and links; optional public GitHub queries and cards.           |
| Contact                    | Known providers with icons based on the URL, a portfolio or personal website, and email; optional label. |

**Add custom section** lets you create multiple sections of your own, with an optional title and blocks for text, bulleted or numbered lists, web links, subheadings, dividers, quotes, images or banners, explicit HTML and literal code. The selector shows ten options with small local previews of their layouts; it does not add example data to the profile. List bullets and numbers are added automatically. Custom sections can be ordered among fixed sections, duplicated as independent copies, and hidden while keeping their content. Deleting an instance removes only that section; if it has content, confirmation is required. Empty or repeated titles are valid and are not used as identifiers.

List-writing assistance is limited to custom sections: start the first line of a text block with `- ` to turn it into a list; Enter adds items, and typing from the last empty item continues as text. Pasting several lines creates list items, and **Convert to text** preserves their content and markers. Other fields remain plain text; Markdown formatting is not enabled globally.

The image block accepts a publicly hosted HTTPS URL and an accessible description. It can display a banner, screenshot or GIF available at that address. It does not upload files or publish a local image when you select or type a path. URL validation is syntactic and does not guarantee that the host responds or serves an image. The preview requests the resource directly from the browser without a server proxy; if it does not load, the description and a link to inspect it are shown. A temporary loading failure does not prevent exporting an accepted URL. Subheadings, dividers and quotes add hierarchy without asking for career history. See [ADR 0014](decisions/0014-custom-visual-blocks.md).

The HTML block offers another optional way to compose profile content, such as a centered title, a row of linked images, a short table or expandable information. It includes a code field, a guide, three examples inserted only when selected, and a preview of the exported HTML. Replacing existing code with an example requires confirmation. The original source is preserved even when analysis removes tags or attributes; notices explain those changes and any problems that block export. Other fields remain plain text.

HTML supports a specific set of tags, alignment and bounded dimensions; it does not support complete pages, CSS or JavaScript. Links must use absolute HTTP/HTTPS URLs, and images must use a public HTTPS URL and an explicit `alt` attribute; `alt=""` marks a decorative image. Relative paths and anchors need to be adapted and are not resolved against the app. The code does not interpret nested Markdown or automatically import other sections from a README. The preview is approximate because GitHub applies its own filters and styles. See [HTML in the editor](editor.md#explicit-html) and [ADR 0015](decisions/0015-explicit-profile-html.md).

The local catalog contains 358 technologies with icons from Devicon, Simple Icons and Lobe Icons. It includes languages, frameworks, ORMs, databases, messaging, infrastructure, development tools and AI tools. Searching does not contact external services or require accounts with those tools. The preview shows icons and names in rows that adapt to available width; exported READMEs reference originals pinned to commits, while the editor uses local SVG copies. Custom names remain available as text. Selection does not represent a skill level or a market ranking.

New tools can use one of nine suggested categories, an existing category or **Uncategorized**. You can create and rename categories, change their order, move and sort tools, or remove a title while keeping its content. These actions and optional notes are in the secondary details. Titles are applied when you leave the field or press Enter. Restoring a draft or changing the interface language preserves category titles and order; **Organize by category** applies suggestions only through an explicit action and confirms before replacing existing titles. See [ADR 0012](decisions/0012-technology-categories.md).

The **Organize new tools** selector explains automatic assignment with examples or the destination you selected. A collapsible guide shows all nine categories and representative tools. Each search result previews where it will be added, including custom tools; an announcement confirms the destination after adding it. The help distinguishes adding new tools from reorganizing existing content.

Contact options include LinkedIn, LeetCode, HackerRank, YouTube, Facebook, Instagram, GitHub, X, Bluesky, DEV Community, Medium, Twitch and Stack Overflow, as well as a portfolio or personal website and email. Choosing a service makes it easier to add a link; the validated URL's domain determines its icon. A custom website uses a generic icon in the form and a text link in the README. The optional label can be customized without changing the detected brand.

Add a contact entry first, then choose a network, website or email and enter its URL. You can repeat services and add multiple custom websites. In the introduction section, Location offers country autocomplete in English and Spanish, with a flag after selection, while keeping free-form text as an alternative. Neither flow requires an account or geolocation and both preserve existing data.

Activity and contributions can be used just to describe a contribution to documentation, review or community work. The GitHub group is optional and collapsible: enter a username, request public activity and choose what to show. All ten card types start disabled: calendar, summary, languages, overview, monthly activity and five Extended families for statistics, languages, repositories, Gists and WakaTime. The overview distinguishes calendar and language data scopes; monthly activity groups by UTC month and identifies partial months. Language data reflects a current sample of code from public repositories, excluding forks; it is not attributed to the calendar period and does not measure skill.

Appearance options include light or dark themes, three palettes and custom layouts, compact or wide size, and 79 named Extended themes. Validated colors and gradients, titles, borders, icons, line spacing and number formats expand customization without free-form CSS. Card appearance is independent of the editor; resetting it preserves usernames, destinations, selected cards, data options and contributions. Cards are generated locally under MIT and retain third-party notices. See [features and limits](github-stats-extended.md) and [ADR 0024](decisions/0024-extended-public-suite-and-mit.md).

Extended lets you choose and order from 18 public counters, set filters and periods, and select from five language layouts with byte or percentage values and explicit weighting. You can add up to twelve public repositories and twelve public Gists; secret Gists are excluded. WakaTime requires a separate username with public activity and languages and shows the last seven days. No WakaTime keys are requested, and the GitHub token is not sent to that provider. Ranking is an explicit choice and is omitted when its inputs are missing or partial. Queries have bounded budgets, samples and history, stated with each result; missing data is never replaced with zero.

Public pull request and issue suggestions are added only when selected; afterward they become editable contributions with an optional personal note. There are no activity minimums, streaks or messages that penalize an empty result. Zero activity, partial data, a nonexistent user, an unconfigured service, exhausted quota and unavailability are explained as distinct situations. Manual editing remains available after a failure, and the last valid result may be shown with its date.

Skills, education and updates have been removed from navigation, forms and output, including for older drafts. Their inherited v1 structures remain stored without being deleted or merged. They do not reappear because they contain data or are marked visible, and their links do not block export. Custom sections do not reactivate retired modules or import their data automatically.

## User flow

1. Open the editor in English or Spanish without creating an account.
2. Choose what to share and configure one section at a time. No fixed section is preselected; adding a custom section includes it and lets you start with a title or content.
3. Use the checkbox to include or hide a section, and use the handle, keyboard or Move up/Move down controls to order included sections.
4. Choose the language for README labels without translating your personal text or changing the interface language.
5. Review the preview and notices, correct any flagged URLs, image descriptions or HTML code, then copy or download `README.md`.

If you selected cards, exporting them requires the app to have a public HTTPS origin configured to host them. In a local environment, you can review the same images through local routes; the requirement is shown before copying or downloading. Deselecting the cards lets you finish a manual profile. Creating a profile does not request tokens or require deployment tasks.

The top bar keeps sections in one horizontal row and identifies the active section. The row scrolls sideways without widening the page. Its checkboxes include or hide sections; handles and left/right arrows reorder included sections. On wide screens, settings and preview occupy two panels; on narrow screens, switch between Edit and Preview. Block samples open from **Add block**, keeping existing content directly accessible. The app explains how to use the file on GitHub; it does not publish on your behalf. The component catalog and Playwright are internal development tools, with no public navigation to the catalog.

The draft is saved in the browser. If storage fails, a notice explains that editing continues in memory and lets you export a valid README. Incompatible data is not replaced automatically. See the [editor guide](editor.md).

## Scope and limits

You can paste an existing README or open a `.md` file, then analyze and review it before confirming. The first version converts content into custom sections, lets you explicitly exclude content, and explains formatting changes or problems. It does not automatically assign content to fixed modules. A single local backup of the complete previous profile and original Markdown is saved and can be downloaded or restored. If storage fails, continuing in memory requires an additional action. Review does not load resources from the document.

The app includes Next.js App Router, TypeScript, a bilingual visual kit and `ProfileDocument` version 2. The mixed `sectionOrder` keeps references to the nine fixed IDs and each `customSections` instance. Visual and HTML blocks extend v2 without changing draft keys or earlier structures; a strict older reader may reject them and must preserve their value. Preview, copy and download use the same generated Markdown. Ordinary text is escaped; custom images and HTML require their explicit, validated blocks, and icons come only from the permitted catalogs.

Optional GitHub queries require server configuration with verifiable public credentials; manual profile creation remains available without it. The app hosts the SVG cards and updates them according to its cache; a graph snapshot is not saved in the draft. There is no AI assistance: a listed AI tool does not imply an integration. The local importer lets you paste or open `.md`, review sections and confirm with a backup. Project files let you download and open the complete profile as local JSON, with review and a separate backup, preserving hidden data and settings. There is no remote sync or custom CSS for README styling.

The single fixed activity section combines inherited contribution and metrics fields without offering metrics separately. Hiding it turns off both flags and preserves data; showing it again includes contributions and any cards that remain selected. Manual contributions can include several links, public images and a repository preview using a description written by the user; move controls choose their order. Activity cards can be shown one or two per row without changing their selection order. The document stores usernames and public destinations, selected cards, options and contributions. Queried public data is temporarily stored in IndexedDB, outside the profile, project files, Markdown and backups. Data is fresh for 30 minutes and may be shown as older data for up to 24 hours. **Search data** authorizes queries for the chosen account; afterward, available coverage is reused and only missing data for selected components is queried. Opening, typing or restoring a draft does not query GitHub. Reloading may restore cached data without authorizing new queries; if storage fails, editing continues in memory with a notice. See [ADR 0031](decisions/0031-browser-persistent-activity-cache.md), [ADR 0039](decisions/0039-contribution-details-and-order.md), and [ADR 0040](decisions/0040-activity-card-columns.md).

Original code uses MIT with attribution to Juan Nicolas Herrera; contributors and third-party materials retain their respective rights holders. Commercial reuse and derivatives are permitted under the terms of their licenses. The [open-source guide](open-source.md) documents notices, the inventory and distribution. The generator's license does not change the rights to content someone includes in their README.

The current draft uses a v2 key. If it does not exist, a valid v1 draft is migrated in memory and its original remains untouched; v2 is not written until an edit. An invalid v2 is not automatically replaced from v1. Migration preserves language, content, IDs, order and visibility from earlier structures. See [ADR 0013](decisions/0013-custom-sections.md).

Structural validation accepts incomplete content and does not prove that a document is exportable. The generator checks active fixed sections and visible custom sections. An invalid link or image URL, an image URL without a description, or a problem in the HTML block prevents all export and points to the field. Completely empty image or HTML source blocks are omitted; hiding a section preserves its data without requiring corrections. HTML analysis has size and complexity limits. Retired fields are preserved only for internal compatibility, as described in [ADR 0008](decisions/0008-focused-profile.md). Icon sources and contact presentation are documented in [ADR 0009](decisions/0009-profile-icons.md); public queries and card hosting in [ADR 0010](decisions/0010-github-activity.md); visual blocks in [ADR 0014](decisions/0014-custom-visual-blocks.md); and explicit HTML in [ADR 0015](decisions/0015-explicit-profile-html.md).
