# Rules for `src/core`

- `CustomSection.title` remains the internal name. In v2 only, `showTitle?: boolean` hides the exported heading when set to `false`; absent/true preserves previous output, with no defaults added during recovery. Preserve the name and formatting when hiding, duplicating, and opening JSON; omit validation errors and title budget for a hidden title, and adjust only implicit heading levels. The ephemeral result of checking public cards does not belong in the document or generator. See [ADR 0042](../../docs/decisions/0042-custom-section-title-visibility.md) and [ADR 0043](../../docs/decisions/0043-public-card-export-check.md).

This area contains `ProfileDocument` v2, its validation, pure operations, activity contracts, and README generation for five fixed sections and repeatable custom sections. `sectionOrder` combines references to nine legacy fixed IDs with references to `customSections`. Skills, education, and current activity are retired; metrics contributes cards to contributions without a separate section. Boundaries are defined in [architecture](../../docs/architecture.md) and [editor](../../docs/editor.md).

- Keep TypeScript pure: no React, Next.js, DOM, `window`, `localStorage`, `fetch`, environment variables, or provider SDKs.
- HTML section detection uses complete headings at the root level, positions from the original HAST, and context between nodes. Keep a heading and its opening sentence together; H2 defines hierarchy except when paired with an initial H1 that has no intervening body, and use H3 when there are no H2 separators. Do not split tables, disclosures, links, or containers; do not infer fixed modules or use the filtered tree to calculate offsets. When uncertain, keep HTML together. mdast paragraphs containing only HTML leaves and whitespace may retain their source to avoid inserting another `p` into an open HTML paragraph. See [ADR 0018](../../docs/decisions/0018-readme-import-with-backup.md).
- Receive explicit data and return deterministic results. Also receive dates or other variable values when they affect output.
- Model information as serializable data. UI functions and service clients do not belong in the saved document.
- Make the document version explicit. Define validation and import compatibility before changing persisted formats.
- `parseProfileDocument` validates v2 or validates v1 and returns its migration to v2, without network or storage. Keep the v1 schema strict and independent; convert `moduleOrder` to fixed references, add `customSections: []`, and preserve data, flags, language, and IDs. Current documents do not contain `moduleOrder`.
- `core/project` opens direct v1/v2 JSON and serializes v2 without changing the model. Limits: 4 MiB UTF-8, depth 32, and 50,000 values; check complexity before Zod and after migration. Prefer indented JSON with LF; use compact JSON near the limit without truncating, and verify it can be reopened. Preserve hidden and legacy data, formatting, and exact source. File validity does not depend on `generateReadme`. See [ADR 0021](../../docs/decisions/0021-project-files-and-recovery.md).
- Validate the complete `sectionOrder`: every fixed ID exactly once and each existing custom section exactly once, with no dangling references. Operations receive valid documents and do not mutate their inputs. Duplicating a custom section must copy its entire structure with new IDs obtained through an explicit function, without partial changes on failure.
- Custom content uses an optional title and discriminated blocks `paragraph`, `list`, `link`, `heading`, `divider`, `quote`, `image`, `html`, and `code`. Extensions are additive within v2; do not change keys or legacy structures. Keep the schema strict and do not insert defaults when reading older formats; older readers may reject new variants or properties and must preserve the original value. Lists support `unordered` or `ordered` styles and text items. Preserve opaque IDs; hiding retains the tree, while deleting removes only that instance and its reference. The generator omits titles without body content, escapes ordinary text, and indents list continuations according to the marker. Without explicit formatting, `heading` produces `###` when there is a section title or `##` without one; `divider` produces `---` and `quote` retains all lines under `>`. Custom links use HTTP/HTTPS, never Contact's `mailto:` exception; report `invalid_url` at `customSections/{index}/blocks/{index}/url`.
- `code` contains exactly `id`, `type`, `source`, and `language`, all strings except the fixed discriminator. Source is literal, with no trimming, normalization, or interpretation; an exactly empty source is omitted and intentional whitespace is preserved. `core/code` maintains a pure catalog/alias resolver, an empty language, and safe unknown tokens up to 64 UTF-16 units. The generator uses fences longer than any run of backticks and limits of 30,000 units per block and 150,000 visible units per document; `invalid_code` points to `source` or `language`, and drafts are never truncated. Hidden content does not consume the budget. Import preserves independent code and language, reports discarded metadata, and respects ambiguous HTML containers; the backup retains the original even if the parser normalizes line endings. See [ADR 0019](../../docs/decisions/0019-code-and-formatting.md).
- Additive formatting: `paragraph.alignment?`, `heading.level?/alignment?`, and `customSection.titleLevel?/titleAlignment?`. Alignment is only `left`, `center`, or `right`; levels are 1/2/3. Absence preserves previous output; duplication copies options and creates new identities. Left alignment uses Markdown; center/right build HAST from literal normalized text, serialize with escaping, and validate through `analyzeProfileHtml`. Share the visible HTML budget and `customHtml` with the explicit block; `invalid_html` points to `text` or `title`. Preserve exact UTF-16 ranges, including aligned titles, without interpreting ordinary content or generating arbitrary styles.
- The `image` block stores only `id`, `type`, `url`, and `alt`. Normalize its URL with `normalizePublicImageUrl`: syntactically public HTTPS domain, with no IP, local host, credentials, fragment, or non-standard port. Do not resolve DNS, request the resource, or promise availability or file format. A completely empty image is omitted; an alternative without a URL produces `invalid_url`; a URL without a normalized alternative produces `missing_image_alt`. Errors use complete paths ending in `url` or `alt`. Hidden sections contribute no errors or images. Generate a Markdown image with an escaped alternative and a URL enclosed in `<` and `>`, without HTML.
- Successful `ReadmeResult` adds `customImages` only when valid custom images exist, in output order and preserving repeats. Its `CustomImageSource` items contain exactly the canonical `src` and plain normalized `alt` equivalent to the Markdown node. This is derived metadata for the preview allowlist; do not persist it or add it to results without images or with errors. Keep the local list index and previous output for documents without new blocks. See [ADR 0014](../../docs/decisions/0014-custom-visual-blocks.md).
- `ReadmeResult.activityCards?` collects only the exact card URLs emitted in the same Markdown, preserving order and repeats; omit it when there are no cards or there are errors. It is pure derived metadata, never persisted authorization or a snapshot. The editor resolves cards through temporary snapshots and the same pure renderers, without another Markdown output or HTTP SVG when customizing. Effective Extended coverage keys are shared between server and browser in `activity/extended-data-plan`; do not introduce environment, network, or secrets. See [ADR 0027](../../docs/decisions/0027-browser-activity-data-cache.md).
- `html` stores only `id`, `type`, and `source`, without normalizing or replacing the original source. `analyzeProfileHtml` analyzes fragments with `hast-util-from-html`, filters an AST with the explicit schema of `hast-util-sanitize`, and serializes with `hast-util-to-html`, without DOM or network. Do not use the default schema as policy: it also allows relative URLs. Validate decoded URLs as absolute HTTP/HTTPS in links and with `normalizePublicImageUrl` in images. HTML requires an `alt` attribute; an explicit empty decorative value is allowed. Omit empty source; report `invalid_html` at `customSections/{index}/blocks/{index}/source` for content, URL, structure, or limit errors. Hidden sections are not analyzed and do not consume budget.
- Apply limits of 30,000 UTF-16 units per block, 1,500 nodes, and depth 32. Before analyzing explicit HTML blocks, check an aggregate limit of 150,000 units of visible source; also add each derived-format unit to the shared budget before analyzing it. Allow only contract-defined tags and attributes: no CSS, scripts, events, full pages, `id`, `name`, classes, `srcset`, `picture`, inline SVG, or MathML. Emit filtering and repair warnings; do not interpret nested Markdown. Preserve h1–h6 levels in exported HTML. A successful result includes `customHtml` only when fragments exist, with `{ html, tree, start, end, headingLevel: 3 | 4 }`: HTML and an allowed HAST tree of complete, closed units, with UTF-16 ranges in the final Markdown. These are derived metadata: do not persist them or include them in errors. Do not mix HTML images with `customImages`. See [ADR 0015](../../docs/decisions/0015-explicit-profile-html.md).
- Encode LF/CR as `&#10;`/`&#13;` entities when serializing canonical HTML so blank lines do not terminate a unit and reactivate Markdown. Do not remove semantic line breaks: `source` preserves the original writing and `tree` retains the actual characters. HTML and tree must represent the same structure and content, without requiring byte-for-byte equality with `toHtml(tree)`. The preview consumes that derived tree and does not reparse the expanded string, whose size may exceed the source limit.
- Preserve data when hiding modules; exclude their output from the README. Do not introduce global requirements for enabling independent sections.
- Do not infer skills or skill levels from commits, stars, detected languages, or contributions.
- Treat profile text and links as untrusted input. Escape content for its output context and restrict protocols; do not accept arbitrary HTML as a shortcut.
- The generator produces escaped Markdown for ordinary fields; only `html.source` interprets authored HTML. Visual formatting builds HTML from escaped text under the same policy; `code.source` is always literal. Share the HTTP/HTTPS policy across active modules and allow `mailto:` only in Contact, never inside HTML. An invalid URL supplied in an active, visible section blocks the complete output and reports the exact field path; an empty optional URL does not need to be filled. Do not resolve relative paths or HTML anchors against the editor origin.
- Combine `contributions` and `metrics` under the fixed contributions reference, with effective inclusion as OR; retain the nine legacy references in the mixed order and omit independent metrics output. Manual contributions appear only with `visibility.contributions`; cards appear only with `visibility.metrics` and non-empty `cards`. Do not require a username for manual content or for metrics with no cards. Do not rewrite flags during generation.
- V2 contributions retain `url` as fallback when `links` is absent; allow up to ten links and three public HTTPS images with non-empty `alt`. The legacy `repository` field is accepted only when recovering older drafts; render it as an ordinary link and description, and fold it into common fields on first edit. V1 remains closed and recovery does not migrate properties. Preserve order and complete error paths. Images alone use `renderProfileHtml`, the shared budget, and exact `customHtml` ranges; do not add `customImages` or make network requests. See [ADR 0039](../../docs/decisions/0039-contribution-details-and-order.md).
- `metrics.cardColumns?: 1 | 2` and `contentOrder?: "activity-first" | "contributions-first"` belong only to v2. Only `createEmptyProfile` chooses two columns; absence preserves one column and activity before contributions, with no defaults on recovery. Render rows as GFM, enlarge SVG typography only in two-column mode, and preserve `cards` order; when the count is odd, the final card gets its own row. `contentOrder` reorders activity and manual contributions within the combined reference. V1 stays closed. See [ADR 0040](../../docs/decisions/0040-activity-card-columns.md) and [ADR 0041](../../docs/decisions/0041-activity-contribution-order-and-readable-cards.md).
- `generateReadme(document, { activityCardBaseUrl? })` remains pure. It receives an explicit public HTTPS origin for cards. Without it, return Markdown with local paths and `exportIssues` containing `activity_not_configured`, even when `success` is true; consumers must prevent exporting that result. A username invalid for visible cards returns `invalid_username`. Never build origins from Host or export localhost.
- Keep `ActivitySnapshot` separate from the persisted document. Validate unknown responses, do not turn failures into zero, and do not generate sample data. SVG renderers receive explicit date and stale state; escape XML, limit text, accept hex colors, and emit no links, external resources, scripts, or `foreignObject`. Languages describe bytes from analyzed repositories; do not infer skills or attribute them to the calendar period.
- V2 `metrics.cards` accepts its seven previous IDs plus `extended-repository`, `extended-gist`, and `extended-wakatime`; v1 retains its original three and rejects Extended appearance/options. `appearance?` combines previous presets, 79 named themes, and bounded hex colors/gradients/dimensions, with no CSS or URLs. `extended?` contains strict statistics options, languages, up to twelve repositories/twelve Gists, and an independent WakaTime username. Do not insert defaults; resetting appearance must not change usernames, destinations, options, selection, or contributions. Share canonical construction and exact route/query validation, without duplicate or unknown parameters. `invalid_activity_options` points to missing destinations or unrepresentable configurations; only profile cards require `metrics.username`. See [ADR 0024](../../docs/decisions/0024-extended-public-suite-and-mit.md).
- Panorama preserves notes about its distinct scopes; monthly activity sums UTC days and marks partial months. Extended retains the pinned MIT license and notices, with public remote snapshots separate from the basic service. Its 18 metrics have nullable values, scope, and partiality; do not invent zeros. Optional ranking starts disabled and uses the formula only when all six inputs are complete; it must not infer skill or an observed population percentile, and is hidden for null/partial inputs. Languages use bytes and repository counts according to the selected weights, identify the weighting, show partiality, group the remainder under Other, and preserve proportions. Resources have validated public identities; WakaTime retains the last seven days and optional dates without inventing them. Do not add network access or hosted services to core; URLs contain only public destinations and validated options, never the draft or manual contributions.
- Always omit `knowledge`, `education`, and `current`, even when their visibility is true. Do not generate headings, content, URL errors, or unsupported-module errors for those retired IDs. Preserve their data, legacy visibility, and references in mixed order; the parser still validates the complete structure. Do not reintroduce retired renderers as a fallback for older drafts.
- Icons are a closed exception in generated output: technologies emit decorative 20 × 20 `img` tags from `core/technologies`, with a pinned URL and `alt=""` beside the escaped visible name; Contact emits 20 × 20 images from `core/contact` with `alt=""` and escaped link text. The preview retains recognition of the previous 32 × 32 technology markup with an alternative name. No attributes for these tokens come from profile text. Recognize exact tokens without widening the exception. Image blocks use exact `customImages` pairs; HTML images belong only to validated `customHtml` units.
- Preserve document order and collections. Omit entries and headings without useful content; do not invent titles. A technology group needs exportable entries. Do not require a name, repository, employment, or public activity to export manual content.
- Technologies retain groups, items, and strings in v1: the pure catalog resolves names, aliases, and suggested categories without network or storage. Organization operations receive new IDs through an explicit function, preserve data, recovered duplicates, and relative order, and resolve local ID collisions when moving items. Removing a category only empties its title. Do not regroup during rendering or recovery; group names are personal content. Escape unrecognized proper names and contexts as text. Translate only generated labels according to `contentLocale`.
- Contact retains `links` with `id`, `label`, and `url`. The pure catalog derives a brand only after URL normalization and checking an explicit domain, without credentials or non-standard ports; the label never determines the icon. A recognized service without a label uses its name; personal websites and unrecognized email retain text links. Do not save provider IDs or icon URLs in v1.
- Catalogs use only pinned sources from Devicon, Simple Icons, Lobe Icons, and flag-icons, with provenance and licenses recorded. A brand or family icon does not imply an integration or measure knowledge. Do not sort the catalog as a skills ranking.
- Location retains the v1 string. An explicit selection stores a Unicode flag and name; recognize only the exact flag and EN/ES name for the same catalog country. Generate a decorative 20 × 15 image from its fixed URL beside the escaped name. Preserve any other value, including custom text with emoji, as complete free text. Do not infer nationality or location, rewrite drafts, or translate their data. The preview accepts only exact allowed flag tokens and does not expand free-form HTML.
- Generate only output accepted by the GitHub target. Cards use Markdown images from exact first-party paths; the preview may resolve those same images locally, without another README. Custom block images load in the browser, without a proxy or server optimizer; a load failure does not change the document or pure result. Editor styling does not authorize CSS or JavaScript in the README. Preview, copy, and download must use the same generator result and respect `exportIssues`.
- Keep shared rules and contracts here, not forms or a registry that imports components. UI composition belongs in `src/modules/` or the editor feature.
- Protect invariants with small, relevant cases: empty fields, hidden modules, order, special characters, and incompatible documents. Avoid huge snapshots as the only evidence.

Consult [architecture](../../docs/architecture.md) for changes that affect other areas.

- Optional presentation typography uses `displayNameTypography` and `headlineTypography` with `italic` or `monospace`. Derive `em` or `code` with literal escaped text, without adding CSS or changing saved strings. V1 stays closed; JSON preserves options, and HTML limits and ranges are shared. Integrated location stays outside these styles; its separate line uses the localized connector «📍 Currently based in» / «📍 Actualmente en» and the catalog flag.

- V2 projects support `titleUrl?` and `cover?: { url, alt }` without defaults during recovery; v1 keeps its closed input. Use the explicit URL to link the title. If `titleUrl` is absent in an older document, use only its first useful legacy link as the destination and generate no additional links or errors for them. Preserve `links` in JSON. The cover requires public HTTPS and a non-empty alternative, shares the HTML policy/budget and exact `customHtml` ranges, and does not expand `customImages`. Legacy `role` and `technologies` remain in the model and are included in generated description. Hidden items do not participate. See [ADR 0033](../../docs/decisions/0033-project-showcase.md) and [ADR 0037](../../docs/decisions/0037-project-description-and-links.md).
- Presentation formatting lives in optional v2 `data.presentation.format`; v1 uses `moduleContentV1Schemas` without these fields. Absence adds no persisted values; name and headline export centered by default unless explicitly aligned. Do not accept, store, or derive an automatic greeting. `locationPlacement?: "displayName" | "headline"` integrates the selected location using `from`/`desde` in the chosen field; if that field has no text, use its own line. Preserve exact strings and catalog flags, and honor overrides. Share derived HTML rendering, budget, and metadata with custom sections; `invalid_html` points to the specific field or both combined fields. See [ADR 0020](../../docs/decisions/0020-presentation-formatting.md) and [ADR 0034](../../docs/decisions/0034-friendly-presentation.md).

- V2 technologies support `layout?: "compact" | "grouped"`. Absence preserves previous output; parsing and migration add no defaults, and v1 stays closed. Only the new-profile factory selects compact. Compact composition builds `kbd` tags, pinned icons, and HAST text; preserves categories/notes/order; and shares the HTML policy, limits, and `customHtml` ranges without expanding `customImages`. All operations and edits preserve layout. See [ADR 0035](../../docs/decisions/0035-compact-technologies.md).
