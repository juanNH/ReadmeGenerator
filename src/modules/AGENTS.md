# Rules for `src/modules`

- A custom section has an internal name in `title` and a separate “Show title in README” checkbox. `showTitle: false` preserves the name and formatting; enabling it again removes the override without deleting the options. Keep the name in navigation and the editor heading even when it is not exported. Implicit subheadings consider only a visible title. See [ADR 0042](../../docs/decisions/0042-custom-section-title-visibility.md).

In Presentation, full greeting and headline examples with emoji belong in placeholders and help text. Per-field typography controls offer GitHub default, italic, and monospace; do not promise font families GitHub does not support. Choosing the default removes only that option, without changing text, alignment, or size.

This area contains the five fixed forms for presentation, technologies, projects, activity and contributions, and contact, as well as the form for custom instances. Knowledge, education, and current activity remain retired, including in older drafts. Metrics are configured within contributions and have no separate navigation. Consult [architecture](../../docs/architecture.md), [editor](../../docs/editor.md), and the authorized scope before expanding functionality.

- The v2 contract retains nine legacy fixed IDs and adds `customSections` with their own references in `sectionOrder`. Only five fixed modules have editing and output. Do not reintroduce retired modules based on their content or visibility. Navigation, form selection, and mixed ordering belong to `features/editor`, not the pure module registry.
- Keep folder and symbol names in English. Resolve interface text through `next-intl` namespaces, with English first and full Spanish support; preserve the language the user wrote for personal profile content.
- Each module owns its form and specific presentation. Reuse the model and rules from `src/core/`; do not define a second profile format inside a component.
- Projects use one optional URL to link the title. For older documents, derive the destination from the first useful link, preserve the legacy collection in JSON, and do not include secondary links in the README. The description combines what the project does, the contribution or role, and technologies; do not restore separate `role` or `technologies` forms, but preserve their legacy values during import/export. The optional v2 cover takes a public HTTPS URL and alt text; it does not upload files or fetch metadata. Preserve field-level errors and all source in JSON. Reuse the existing derived-HTML flow and `PublicProfileImage` without expanding `customImages`. Output order remains title, description, and cover. See [ADR 0033](../../docs/decisions/0033-project-showcase.md) and [ADR 0037](../../docs/decisions/0037-project-description-and-links.md).
- Technologies expose the README layout near the top: compact or headings by category. Preserve optional `layout` through all edits and do not rewrite it when opening a draft; absence means headings. Do not remove categories or notes to make output compact. See [ADR 0035](../../docs/decisions/0035-compact-technologies.md).
- Manual contributions allow up to ten links and three public HTTPS images with alt text. Keep legacy URLs and previews as ordinary links when editing, combine the prior description non-destructively, show field-level errors, preserve ordering, and allow contributions to move through accessible buttons; never fetch repository metadata. Preview and export use the same Markdown and validated derived HTML. See [ADR 0039](../../docs/decisions/0039-contribution-details-and-order.md).
- Distinguish selection, inclusion, and deletion. Selection changes the form in the settings panel; the checkbox controls whether it appears in the README and preserves content when hidden. Hiding the active section keeps its form editable with an exclusion notice. Deletion requires an interaction that explains its effect.
- All modules are optional. A block must not require another block unless there is a real, documented data dependency.
- Design a brief personal profile with an open-ended introduction and secondary details. Avoid asking twice about interests or current activity. Preserve retired data internally without editing, merging, inferring, or deleting it.
- Keep ephemeral form state, persisted profile data, and remote data separate. Do not copy derived data into multiple sources of truth.
- The custom form edits an optional title and blocks for text, bulleted/numbered lists, web links, subheadings, dividers, highlighted text, images/banners, explicit HTML, and literal code. The selector offers ten buttons with decorative local samples, accessible names, and descriptions in EN/ES; do not preload example text or images into real data. Keep first-line `- ` detection, Enter/paste list items, and text conversion limited to paragraphs and lists in this form, respecting IME composition and selection. Do not extend those behaviors to HTML or literal code, subheadings, highlighted text, presentation, notes, or fixed-module fields. Focus the created input or a stable target when removing, converting, or reordering; use a divider's heading as the target because it has no editable field. Announce actions in EN/ES.
- The image block takes a public HTTPS URL and alt text, without file uploads. Associate `invalid_url` and `missing_image_alt` with the full path and show help and errors on the corresponding field. Reuse the generator for validation; do not add another contract or availability checks. The preview loads only exact `customImages` pairs, directly in the browser with lazy loading, asynchronous decoding, and no referrer; do not use a proxy or server optimizer. A load failure shows the alt text and a link, is ephemeral, and does not block export of an accepted URL. See [ADR 0014](../../docs/decisions/0014-custom-visual-blocks.md).
- HTML is edited in labeled `CodeEditor`, with lazy highlighting and a plain-text alternative, and preserves `source` exactly as written. Use `analyzeProfileHtml` for filtering warnings and issues; do not add another validation policy. Associate `invalid_html` with the full path ending in `source`, allow correction, and preserve code when hiding, duplicating, or recovering. Show a collapsible guide, limits, and inspectable exported HTML, with EN/ES text. The three examples for a centered heading, table, and disclosure are inserted only by explicit choice and confirm replacement of non-empty source; the samples load no resources. Do not interpret Markdown inside the block or expand other fields. Explain that links use absolute HTTP/HTTPS, images use public HTTPS with a required `alt` attribute (`alt=""` is decorative only), and CSS, JavaScript, and unsupported attributes are filtered. Do not present the preview as an exact GitHub replica. See [ADR 0015](../../docs/decisions/0015-explicit-profile-html.md).
- Coordinate duplication, include/hide, and deletion of instances through the profile's pure operations in `features/editor`. Do not share objects or IDs with the copy, delete on hide, or treat titles as identifiers. Duplicate or empty titles are valid; the UI distinguishes them without changing exported text.
- Activity and contributions keep manual contributions available without a GitHub username. Offer ten types, disabled initially, with local samples. “Search data” appears below the username and works without cards: it loads common information and activates the account. Afterwards, selecting components or customizing automatically queries only missing coverage, grouping rapid changes over 300 ms; covered options render cards locally without HTTP SVG or JSON. Valid applied resources that are selected may also load after Search. Opening, recovery, or typing an account that has not been searched does not query. Show progress and errors even without cards; do not retry failures in a loop, and respect reduced motion. Optional contribution search uses a separate action. Repositories and Gists allow twelve destinations each; WakaTime uses a separate username. Do not request tokens or deployment configuration. See [ADR 0027](../../docs/decisions/0027-browser-activity-data-cache.md) and [ADR 0029](../../docs/decisions/0029-account-first-activity-search.md).
- Hooks validate snapshots, check identity and options, cancel queries, and discard late responses. The public card cache is retained temporarily in separate IndexedDB storage, with identity/scope/original timestamp and an in-memory fallback. Restoring it does not query or authorize network access; missing or expired data waits for Search. Show saving/saved/fallback states in EN/ES. Unmounting preserves the store; replacing or clearing the profile purges it. Do not save secrets, errors, permissions, SVGs, or snapshots in `ProfileDocument`. Persist only `metrics.username/cards/appearance?/extended?/cardColumns?/contentOrder?` and suggestions explicitly chosen as manual contributions with new IDs. `cardColumns` selects one or two cards per row; absence preserves the previous layout, and only a new profile starts with two. Two-column mode increases text size in the same local and public renderers. `contentOrder` chooses activity or contributions first; absence preserves activity-first. Preserve selected order and preview GFM tables accessibly. Distinguish zero, partial, and missing data. Do not add highlights automatically or deduplicate them by title. See [ADR 0031](../../docs/decisions/0031-browser-persistent-activity-cache.md), [ADR 0040](../../docs/decisions/0040-activity-card-columns.md), and [ADR 0041](../../docs/decisions/0041-activity-contribution-order-and-readable-cards.md).
- Offer Extended appearance and options through core contracts, decorative local samples, and EN/ES controls, with no free-form CSS or persisted sample data. Reset removes appearance only. Preserve usernames, destinations, options, cards, contributions, and missing defaults during recovery. Explain the bounded sample/history and differences in the [compatible suite](../../docs/github-stats-extended.md). The authorized ranking starts disabled; only an explicit choice enables its activity formula, and help must clarify it does not measure skill or an observed population percentile. Hide it when complete inputs are missing; do not show skill levels. See [ADR 0024](../../docs/decisions/0024-extended-public-suite-and-mit.md).
- Distinguish not configured, user not found, rate limit, unavailable, and zero activity. Allow cards from older drafts to remain selected or be unchecked even when a query fails. Missing credentials or a public origin do not block manual contributions.
- Forms need labels, instructions, associated errors, and keyboard operation. Provide accessible alternatives to dragging items.
- In lists, create new UI IDs with `crypto.randomUUID()`, preserve recovered IDs as opaque strings, and use independent DOM IDs. Do not encode draft IDs to form DOM IDs. Project technologies are `string[]`; do not add identifiers to the persisted format. Adding focuses the new input; removing focuses a neighbor or the add button.
- Technologies use local autocomplete, chips with icon and name, and custom text as an alternative. Offer a suggested category or existing destination for new tools; create, rename, reorder, and move using accessible secondary controls. Moving a tool requires an explicit action after selecting a destination, without moving focus when using the selector. Removing a category preserves its tools and hides only the title. Do not regroup during recovery or language changes; organizing by category is explicit and confirms replacement of existing titles. Preserve legacy technology structures within v2, opaque IDs, groups/contexts, and keyboard alternatives. Hide empty unnamed internal groups without deleting them. Use only allowed SVG and metadata, without remote searches or custom image URLs.
- Contact first adds a row and focuses its provider, website, or email selector. Choosing preserves focus and Tab advances to the URL; do not force focus changes while moving through options with arrow keys. Keep one add button at the end, including when the list is empty. Allow repeated providers and websites. The label belongs in optional details. Derive the icon from the URL through `core/contact`, never from the label or an ephemeral selection. The choice only guides the placeholder; it never replaces the URL or name and does not change v1 `links`; derive it from the address during recovery. Keep decorative icons beside readable names.
- Presentation offers optional free-text location with EN/ES country suggestions and local flags from `core/location`. Only an explicit choice adds the Unicode prefix that retains the flag and name in the v1 string; do not guess countries from existing text or use geolocation. Changing interface language does not translate saved content. Use a keyboard-accessible combobox with Escape, announcements, and readable text; the flag is decorative.
- Associate URL errors with the full path, including project and link indices. Optional web links in content do not allow `mailto:`; Contact keeps its email policy. Do not duplicate export validation in forms.
- Reuse `src/components/ui/` and tokens. Do not introduce a separate visual system for a module.
- Keep exportable formatting logic in the pure generator; do not build a different README inside the preview.
- Access services through the agreed boundary. Do not import `src/server/` from Client Components or expose secrets in the browser.
- The first search prepares all 18 counters and languages for the current scope, using form options even when no cards are selected. Changing checkboxes or order reuses that coverage without network access; new years/filters may query. Do not confuse counter prefetch with history, pagination, or unlimited destinations. See [ADR 0030](../../docs/decisions/0030-all-profile-counters-prefetch.md).
- Avoid direct dependencies between modules. Share rules in `core` and flow coordination in `features` when there is a concrete need.
- Sharing projects or contributions is optional. Do not make metrics or public activity a requirement for creating a profile.

Read [architecture](../../docs/architecture.md) and the feature plan before changing shared contracts.

- Literal code uses `{ id, type: "code", source, language }`, without HTML interpretation or list helpers. Reuse `core/code` for suggestions, normalization, and limits; associate `invalid_code` with `source` or `language`. Empty source is not exported; loading a sample JSON requires an explicit choice and confirmation before replacing content. Use `CodeEditorHandle` for focus/selection; do not assume a textarea. Tab exits the editor and indentation commands are explicit. Preserve source, selection, and local history when switching modes.
- Formatting is limited to section titles, paragraphs, and custom headings. Use optional `titleLevel/titleAlignment`, `paragraph.alignment`, and `heading.level/alignment` properties; do not insert defaults during recovery. Converting a paragraph/heading preserves its ID, text, and alignment. The UI does not generate output HTML: derive everything from the pure generator and keep `skipHtml` outside verified units. See [ADR 0019](../../docs/decisions/0019-code-and-formatting.md).

- Presentation offers name, headline, and bio, with writing help in each field and visible location with country suggestions. Location remains optional free text; allow choosing whether it appears beside the name or headline, preserving its explicit flag. A greeting is only a suggestion for the full headline; never add it automatically. Do not infer a profession or country or insert examples through buttons. Name and headline are centered by default; alignment and level overrides are editable in the collapsible formatting panel. Do not persist defaults; resetting formatting removes only that property. Associate `invalid_html` with the relevant `data/presentation` field path. Do not reintroduce knowledge, education, or current activity. See [ADR 0034](../../docs/decisions/0034-friendly-presentation.md).
