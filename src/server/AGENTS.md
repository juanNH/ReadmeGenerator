# Reglas de `src/server`

Este ámbito implementa lecturas opcionales de GitHub y estadísticas públicas WakaTime, y reserva la asistencia con IA para una feature posterior. GitHub requiere configuración exclusiva del servidor; WakaTime usa una cuenta pública independiente sin credenciales. No presentar datos ficticios ni una integración GitHub sin configurar como una consulta real completada.

- Marcar las implementaciones exclusivas del servidor con `import "server-only"`. No importar este ámbito desde componentes o utilidades que llegan al navegador.
- Mantener secretos en variables de entorno del servidor, fuera de Git y de `NEXT_PUBLIC_`. No registrar tokens, documentos personales completos ni respuestas sensibles.
- Validar y limitar entradas al llegar desde una ruta, acción o servicio externo. Los tipos TypeScript no validan solicitudes en ejecución.
- Mantener Route Handlers y Server Actions pequeños. Concentrar en este ámbito el acceso externo y la traducción de sus respuestas al contrato interno.
- Tratar como públicas las rutas públicas aunque sus consumidores previstos sean componentes propios. Definir límites de uso, tamaño, tiempo de espera y manejo de errores antes de exponer operaciones costosas.
- GitHub usa un endpoint GraphQL fijo, solicitudes POST sin caché de fetch, redirecciones deshabilitadas, timeout global de 15 s y respuestas de hasta 2 MiB. Validar usuario, envelope GraphQL y snapshot; errores HTTP 200 tampoco son éxito. No aceptar endpoints, query GraphQL ni URLs de repositorios arbitrarias del navegador.
- Admitir un PAT classic dedicado mediante `GITHUB_TOKEN`; verificar `x-oauth-scopes` presente y vacío o exactamente `public_repo` en cada respuesta antes de consumir datos. Preferir solo `public_repo` para GraphQL de repositorios públicos; rechazar cualquier scope adicional, incluidos `repo` y `read:user`, y tokens no verificables como fine-grained. El cliente solo ejecuta lecturas aunque el scope público permita otras operaciones. Validar `isViewer` y que `user.login` coincida con el usuario solicitado sin distinguir mayúsculas; admitir `userViewType: PUBLIC`, o `PRIVATE` únicamente cuando `isViewer` sea verdadero. Ese enum describe la vista autenticada, no permite detectar un ajuste de perfil privado. Filtrar repositorios públicos propios no forks y aportes restringidos o privados; no exponer `isViewer` ni `userViewType` en el snapshot. Solo mostrar recuentos privados anónimos que el perfil haya hecho públicos. Ver [ADR 0022](../../docs/decisions/0022-token-owner-public-activity.md).
- Mantener cachés en memoria acotadas: hasta 512 snapshots/fallos, frescura de 30 minutos, último resultado válido hasta 24 horas ante fallos transitorios, cuatro consultas distintas simultáneas y 60 por minuto por proceso. Deduplicar consultas; respetar Retry-After, cuotas y cooldown. No servir stale ante `not_found` o `not_configured`. Cambiar credenciales invalida resultados anteriores. Estos límites no sustituyen protección distribuida del despliegue.
- Consultar como máximo tres páginas de 100 repositorios y 20 lenguajes por repositorio; retener hasta 100 lenguajes agregados y señalar truncamiento. La tarjeta básica muestra porcentajes de bytes; Extended puede ponderar bytes/cantidad de repositorios y debe indicarlo. Ninguna mide conocimientos ni toda la cuenta. Las sugerencias son aportes públicos del período y nunca se agregan solas al documento.
- Extended mantiene un snapshot separado con 18 métricas de valor nullable, alcance y parcialidad; limita cada operación a 15 solicitudes/15 s de red, 300 repositorios, diez años de histórico y tres páginas de 100 por conexión de discusiones. Los filtros deben conservar alcance público comprobable; exclusiones por nombre afectan a estrellas/lenguajes, no a búsquedas históricas de PR/issues/commits. Datos faltantes o parciales no son cero completo. El histórico público resta recuentos privados anónimos del calendario. Extended y recursos comparten un planificador de cuatro consultas activas y 60 lanzamientos/minuto, con cola FIFO de 32 esperas y hasta 45 s en cola; revalidar credenciales y cooldown al lanzar, iniciar entonces el plazo de red y deduplicar también encolados. Sus cachés admiten hasta 512 entradas combinadas por servicio con claves de identidad/opciones/credenciales y aislamiento de generaciones anteriores. La actividad básica conserva su frontera independiente. No presentar estos límites por proceso como protección distribuida agregada.
- Las tarjetas de repositorio/Gist aceptan solo identificadores acotados, endpoints GitHub fijos y metadatos con identidad/visibilidad públicas verificadas; excluir Gists secretos incluso accesibles por ID. Descartar el contenido incrustado en REST de Gist; no consultar raw_url ni exponer o persistir esa fuente. WakaTime usa únicamente `https://api.wakatime.com/api/v1/users/{username}/stats/last_7_days` sin token GitHub ni claves adicionales; exigir actividad y lenguajes visibles y actualizados, conservar rango y fechas opcionales sin inventarlas. No consultar proyectos, máquinas o actividad privada. Los contadores públicos opcionales de aportes a un repositorio usan un usuario explícito y la frontera Extended. Ver [ADR 0024](../../docs/decisions/0024-extended-public-suite-and-mit.md).
- La caché Extended registra cobertura por campo y dependencias efectivas, excluyendo selección, orden y presentación. Un null/partial consultado es cobertura; un dato no consultado no es cero. Consultar faltantes y coordinar solicitudes compatibles en vuelo con hasta 32 seguidores por usuario y un plazo total de 60 s heredado por la cola y la red. Conservar fecha por campo y usar la más antigua al combinar, sin mezclar intervalos temporales UTC; agregar un contador no rejuvenece los anteriores. Mantener diferencias de roles por defecto entre estadísticas y repositorios/lenguajes, dependencias de ranking/porcentaje y aislamiento por usuario, credenciales y día UTC. Un fallo global de credenciales invalida también su generación en vuelo. Ver [ADR 0025](../../docs/decisions/0025-activity-data-cache-and-preview-batching.md).
- `APP_URL` identifica el origen público HTTPS de este despliegue y de sus SVG; validarlo sin usar Host. Las rutas JSON y SVG no exponen tokens, respuestas crudas ni errores de proveedores. Los SVG son pasivos y llevan CSP restrictiva, nosniff y caché pública; los no disponibles tienen estado propio y no ceros inventados.
- Distinguir datos capturados al generar de recursos que se actualizan posteriormente. Las tarjetas SVG están alojadas por esta aplicación y vuelven a consultar la actividad según caché; el README guarda una URL estable, no una captura ni snapshots personales.
- Para futura IA, enviar únicamente los datos necesarios para la acción solicitada y validar las sugerencias contra el contrato del perfil. Su aplicación necesita una revisión explícita de los cambios por parte del usuario.
- La asistencia propondrá cambios sobre datos existentes; el generador de `core` seguirá produciendo el README. No inventar formación, experiencia, proyectos o niveles de conocimiento.
- Separar contratos serializables de las implementaciones del proveedor. No instalar SDKs ni agregar credenciales hasta que exista una feature aprobada que los use.
- Verificar integraciones con respuestas controladas y errores relevantes. Las pruebas habituales no realizan llamadas facturables ni requieren secretos reales.
