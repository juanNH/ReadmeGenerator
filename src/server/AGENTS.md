# Rules for `src/server`

- Explicit public card checks validate exact canonical URLs against the configured origin, without arbitrary hosts or paths. Send anonymous HEAD requests only, with no cookies/Authorization and no redirects; require SVG MIME type and ready/stale status. Keep body/time limits, 32 URLs, 4 active requests, 1 simultaneous check, 12 checks, and 60 HEAD requests per process per minute; cancel on failure or abort and return no bodies or Location. Distinguish protection, incompatibility, data, and temporary failures. Do not change hosting or credentials to mask a failure. See [ADR 0043](../../docs/decisions/0043-public-card-export-check.md).

This area implements optional GitHub reads and public WakaTime statistics, and reserves AI assistance for a future feature. GitHub requires server-only configuration; WakaTime uses a separate public account with no credentials. Do not present fictional data or an unconfigured GitHub integration as a completed real query.

- Mark server-only implementations with `import "server-only"`. Do not import this area from components or utilities that reach the browser.
- Keep secrets in server environment variables, outside Git and `NEXT_PUBLIC_`. Do not log tokens, complete personal documents, or sensitive responses.
- Validate and limit inputs when they arrive from a route, action, or external service. TypeScript types do not validate runtime requests.
- Keep Route Handlers and Server Actions small. Keep external access and translation of responses into the internal contract in this area.
- Treat public routes as public even when their intended consumers are first-party components. Define usage, size, timeout, and error-handling limits before exposing costly operations.
- GitHub uses a fixed GraphQL endpoint, POST requests without fetch caching, disabled redirects, a 15 s global timeout, and responses up to 2 MiB. Validate the user, GraphQL envelope, and snapshot; HTTP 200 errors are not success. Do not accept arbitrary endpoints, GraphQL queries, or repository URLs from the browser.
- Accept a dedicated classic PAT through `GITHUB_TOKEN`; verify that `x-oauth-scopes` is present and empty or exactly `public_repo` in every response before consuming data. Prefer only `public_repo` for public repository GraphQL queries; reject any additional scope, including `repo` and `read:user`, and unverifiable tokens such as fine-grained tokens. The client performs read-only operations even though the public scope allows other operations. Validate `isViewer` and that `user.login` matches the requested user case-insensitively; allow `userViewType: PUBLIC`, or `PRIVATE` only when `isViewer` is true. That enum describes the authenticated view; it does not reveal a private-profile setting. Filter out non-public repositories, forks, and restricted/private contributions; do not expose `isViewer` or `userViewType` in the snapshot. Show only anonymous private counts that the profile owner has made public. See [ADR 0022](../../docs/decisions/0022-token-owner-public-activity.md).
- Keep in-memory caches bounded: up to 512 snapshots/failures, 30-minute freshness, the last valid result for up to 24 hours during transient failures, four distinct concurrent queries, and 60 per process per minute. Deduplicate queries; respect Retry-After, quotas, and cooldown. Do not serve stale data for `not_found` or `not_configured`. Credential changes invalidate previous results. These limits do not replace distributed deployment protection.
- Query at most three pages of 100 repositories and 20 languages per repository; retain up to 100 aggregated languages and mark truncation. The basic card shows byte percentages; Extended may weight bytes/repository counts and must identify that. Neither measures skill or represents the whole account. Suggestions are public contributions from the period and are never added to the document automatically.
- Extended maintains a separate snapshot with 18 nullable metrics, scope, and partiality; each operation is limited to 15 network requests/15 s, 300 repositories, ten years of history, and three pages of 100 per discussion connection. Filters must preserve verifiable public scope; name exclusions apply to stars/languages, not historical PR/issue/commit searches. Missing or partial data is not a complete zero. Public history subtracts anonymous private counts from the calendar. Extended and resource queries share a scheduler of four active queries and 60 launches/minute, with a FIFO queue of 32 waiters and up to 45 s in queue; revalidate credentials and cooldown when launching, start the network timeout then, and deduplicate queued requests too. Its caches allow up to 512 combined entries per service, keyed by identity/options/credentials and isolated across generations. Basic activity keeps an independent boundary. Do not present these per-process limits as aggregate distributed protection.
- Repository/Gist cards accept only bounded identifiers, fixed GitHub endpoints, and metadata whose public identity/visibility has been verified; exclude secret Gists even when accessible by ID. Discard content embedded in the Gist REST response; do not query `raw_url` or expose or persist that source. WakaTime uses only `https://api.wakatime.com/api/v1/users/{username}/stats/last_7_days` without a GitHub token or additional keys; require visible, current activity and languages, and preserve optional range and dates without inventing them. Do not query projects, machines, or private activity. Optional public contribution counters for a repository use an explicit user and the Extended boundary. See [ADR 0024](../../docs/decisions/0024-extended-public-suite-and-mit.md).
- Extended cache tracks coverage per field and effective dependencies, excluding selection, order, and presentation. A queried null/partial value counts as coverage; an unqueried value is not zero. Query missing data and coordinate compatible in-flight requests with up to 32 followers per user and a total 60 s timeout inherited by queue and network. Preserve timestamps per field and use the oldest when combining; do not mix UTC intervals. Adding a counter does not refresh older ones. Preserve default-role differences between statistics and repositories/languages, ranking/percentage dependencies, and isolation by user, credentials, and UTC day. A global credential failure also invalidates its in-flight generation. See [ADR 0025](../../docs/decisions/0025-activity-data-cache-and-preview-batching.md).
- `APP_URL` identifies the public HTTPS origin of this deployment and its SVGs; validate it without using Host. If empty and `VERCEL_ENV` is exactly `production`, the bare `VERCEL_PROJECT_PRODUCTION_URL` domain may be used with HTTPS and the same validation. A non-empty invalid explicit value does not enable fallback. Do not use `VERCEL_URL`, branch aliases, or the request; local and Preview require an explicit origin. See [ADR 0036](../../docs/decisions/0036-production-card-origin.md). JSON and SVG routes do not expose tokens, raw responses, or provider errors. SVGs are passive and include restrictive CSP, nosniff, and public caching; unavailable states are distinct and do not fabricate zeros.
- Distinguish data captured during generation from resources that update later. SVG cards are hosted by this application and query activity again according to cache state; the README stores a stable URL, not a capture or personal snapshot.
- For future AI, send only the data needed for the requested action and validate suggestions against the profile contract. Applying them requires explicit user review of the changes.
- Assistance will propose changes to existing data; the `core` generator will continue to produce the README. Do not invent education, experience, projects, or skill levels.
- Separate serializable contracts from provider implementations. Do not install SDKs or add credentials until an approved feature uses them.
- Verify integrations with controlled responses and relevant errors. Routine tests do not make billable requests or require real secrets.
