# Reglas de `src/server`

Este ámbito implementa la lectura opcional de actividad pública de GitHub y reserva la asistencia con IA para una feature posterior. La integración requiere configuración del servidor; no presentar datos ficticios ni un servicio sin credenciales como una consulta real completada.

- Marcar las implementaciones exclusivas del servidor con `import "server-only"`. No importar este ámbito desde componentes o utilidades que llegan al navegador.
- Mantener secretos en variables de entorno del servidor, fuera de Git y de `NEXT_PUBLIC_`. No registrar tokens, documentos personales completos ni respuestas sensibles.
- Validar y limitar entradas al llegar desde una ruta, acción o servicio externo. Los tipos TypeScript no validan solicitudes en ejecución.
- Mantener Route Handlers y Server Actions pequeños. Concentrar en este ámbito el acceso externo y la traducción de sus respuestas al contrato interno.
- Tratar como públicas las rutas públicas aunque sus consumidores previstos sean componentes propios. Definir límites de uso, tamaño, tiempo de espera y manejo de errores antes de exponer operaciones costosas.
- GitHub usa un endpoint GraphQL fijo, solicitudes POST sin caché de fetch, redirecciones deshabilitadas, timeout global de 15 s y respuestas de hasta 2 MiB. Validar usuario, envelope GraphQL y snapshot; errores HTTP 200 tampoco son éxito. No aceptar endpoints, query GraphQL ni URLs de repositorios arbitrarias del navegador.
- Admitir un PAT classic dedicado mediante `GITHUB_TOKEN`; verificar `x-oauth-scopes` presente y vacío o exactamente `public_repo` en cada respuesta. Preferir solo `public_repo` para GraphQL de repositorios públicos; rechazar cualquier scope adicional, incluidos `repo` y `read:user`, y tokens no verificables como fine-grained. El cliente solo ejecuta lecturas aunque el scope público permita otras operaciones. Rechazar perfiles privados, filtrar repositorios públicos propios no forks y aportes restringidos o privados. Solo mostrar recuentos privados anónimos que el perfil haya hecho públicos.
- Mantener cachés en memoria acotadas: hasta 512 snapshots/fallos, frescura de 30 minutos, último resultado válido hasta 24 horas ante fallos transitorios, cuatro consultas distintas simultáneas y 60 por minuto por proceso. Deduplicar consultas; respetar Retry-After, cuotas y cooldown. No servir stale ante `not_found` o `not_configured`. Cambiar credenciales invalida resultados anteriores. Estos límites no sustituyen protección distribuida del despliegue.
- Consultar como máximo tres páginas de 100 repositorios y 20 lenguajes por repositorio; retener hasta 100 lenguajes agregados y señalar truncamiento. Los porcentajes son bytes analizados, no conocimientos ni un resumen completo de toda la cuenta. Las sugerencias son aportes públicos del período y nunca se agregan solas al documento.
- `APP_URL` identifica el origen público HTTPS de este despliegue y de sus SVG; validarlo sin usar Host. Las rutas JSON y SVG no exponen tokens, respuestas crudas ni errores de proveedores. Los SVG son pasivos y llevan CSP restrictiva, nosniff y caché pública; los no disponibles tienen estado propio y no ceros inventados.
- Distinguir datos capturados al generar de recursos que se actualizan posteriormente. Las tarjetas SVG están alojadas por esta aplicación y vuelven a consultar la actividad según caché; el README guarda una URL estable, no una captura ni snapshots personales.
- Para futura IA, enviar únicamente los datos necesarios para la acción solicitada y validar las sugerencias contra el contrato del perfil. Su aplicación necesita una revisión explícita de los cambios por parte del usuario.
- La asistencia propondrá cambios sobre datos existentes; el generador de `core` seguirá produciendo el README. No inventar formación, experiencia, proyectos o niveles de conocimiento.
- Separar contratos serializables de las implementaciones del proveedor. No instalar SDKs ni agregar credenciales hasta que exista una feature aprobada que los use.
- Verificar integraciones con respuestas controladas y errores relevantes. Las pruebas habituales no realizan llamadas facturables ni requieren secretos reales.
